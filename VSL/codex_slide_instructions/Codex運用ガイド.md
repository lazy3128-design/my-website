**バージョン**：v1.0

**目的**：UTAGE VSLスライド生成タスクをCodexに依頼するときに、何を渡してどう指示するかの完全マニュアル。

## 1. 渡すべきファイル一覧

Codexのチャット欄（ファイル添付機能）に**以下5種を全部アップロード**してください：

| # | ファイル | 役割 | 必須 |
|---|---|---|---|
| 1 | **UTAGE_VSL_スライド制作指示書_for_Codex.md** | 全パターン定義・色・フォントの仕様書 | ✅ 必須 |
| 2 | **utage_palette_reference.png** | 色見本（視覚的に色感を確認させる） | ✅ 必須 |
| 3 | **10slides_sample_data.json** | 13枚分のスライドデータ（実は13枚） | ✅ 必須 |
| 4 | **render_slides_reference.py** | Python参考実装（パターン①②③④⑤の骨格） | ✅ 必須 |
| 5 | **6名分の顔写真** | カード型スライド用（029-2/4/6） | ✅ 必須 |

### 顔写真の準備

以下6ファイルを1つのフォルダ `/photos` にまとめてZIPでアップロードするか、個別添付：

## 2. Codexチャット欄に書く初回指示文（コピペ用）

下のメッセージを丸ごとコピーしてCodexのチャット欄に貼り付けてください：

```
タスク：UTAGE VSLスライド生成システムの実装と13枚サンプル出力

【添付ファイル】
1. UTAGE_VSL_スライド制作指示書_for_Codex.md（仕様書）
2. utage_palette_reference.png（色見本）
3. 10slides_sample_data.json（13枚分のデータ）
4. render_slides_reference.py（参考実装）
5. photos/*.jpg（6名分の顔写真）

【お願いしたいこと】
仕様書「UTAGE_VSL_スライド制作指示書_for_Codex.md」の**章11・章12を必ず先に読んでください**。
そのうえで以下を実施してください：

(A) 8つのレンダリング関数を実装（Python + Pillow使用）
  - render_pattern_1_gradient
  - render_pattern_2_deep_purple
  - render_pattern_3_message
  - render_pattern_3_card
  - render_pattern_3_list
  - render_pattern_3_matrix
  - render_pattern_4_sentimental
  - render_pattern_5_dark
  
  参考：render_slides_reference.py に骨格あり。ただし簡易実装なので、品質を上げる方向で改善してOK。
  
(B) 10slides_sample_data.json の13枚分のデータを上記関数に流して、
   /slides/ ディレクトリに slide_XXX.png（1920×1080）を13枚出力

(C) 13枚を3列×5行のサムネ一覧画像として /tmp/sample_thumbs.png にまとめて出力
   （横並び一覧で揃い具合をチェックできるように）

【絶対ルール（仕様書 章0と章11も参照）】
- 1枚ずつ自由生成NG（必ず関数を経由）
- 色は仕様書のUTAGEパレットのみ使用（HEX指定）
- 大賀VSLの煽り赤（#FF3D2F系）は禁止
- 顔ワイプエリア（右上480×270px）と字幕エリア（下120px）は必ず空白
- フォントは Noto Sans JP / ヒラギノ角ゴ / 游ゴシック のいずれか
- 出力サイズは1920×1080 PNG固定

【特に確認したい一貫性テスト】
- 029-2 / 029-4 / 029-6 の3枚は同じp3_card関数で生成されるため、
  顔写真位置・文字サイズ・余白が完全に揃うこと

【完了後のレポート】
最後に、以下を簡潔に報告してください：
- 各関数のシグネチャ
- 出力した13枚のリスト
- 自己評価（一貫性は保てたか／パターン解釈に迷った箇所はあるか）
```

## 3. Codexからのレスポンス後の確認チェックリスト

Codexが13枚を出してきたら、以下を目視確認：

### A. 全体一貫性
- [ ] 13枚すべて1920×1080か
- [ ] フォントが全枚で揃っているか（Noto Sans JP想定）
- [ ] 右上480×270pxが全枚で空白か（顔ワイプ用）
- [ ] 下120pxが全枚で空白か（字幕用）

### B. パターン別品質
- [ ] **p1_gradient（4枚）**：S027/078/100/193のグラデ角度・色・テクスチャが完全に揃うか
- [ ] **p2_deep_purple（1枚）**：S002の背景が `#6C3D9F`、煽り赤NG
- [ ] **p3_card（3枚連続）**：S029-2/4/6の顔写真位置・文字サイズ・余白が完全に揃うか ← **最重要チェック**
- [ ] **p3_list（1枚）**：S028の箇条書きが①②③④⑤形式
- [ ] **p3_message（1枚）**：S080の数値スタッツが大きく表示されているか
- [ ] **p3_matrix（1枚）**：S074の2カラム比較表が正しく機能しているか
- [ ] **p4_sentimental（1枚）**：S001がブランド色寄せの抽象グラデ
- [ ] **p5_dark（1枚）**：S174が`#1A1F36`紫青もや

### C. 致命的NGの有無
- [ ] 煽り赤 `#FF3D2F` が混入していないか
- [ ] MS Pゴシック・メイリオ・装飾フォントが使われていないか
- [ ] クリップアートや古臭いイラストが混入していないか
- [ ] 文字サイズが28pt未満（スマホで読めないサイズ）になっていないか

## 4. 追加修正を依頼するときのテンプレ

サンプル13枚を見て修正が必要な場合、Codexに以下のように依頼します：

```
ありがとう、確認しました。以下を修正してください：

【修正1】p3_card のレイアウトで、顔写真の位置を50pxほど下にずらしてください。
  対象：slide_029-2.png / slide_029-4.png / slide_029-6.png（3枚すべて）
  ※関数を1か所修正すれば3枚一括で反映されるはず

【修正2】p1_gradient のグラデが暗く見えるので、ブランドブルー側を10%明るくしてください。
  対象：slide_027.png / slide_078.png / slide_100.png / slide_193.png（4枚すべて）

【修正3】p2_deep_purple の左上コーラル帯が小さすぎるので、幅12px×高さ300pxに変更してください。
  対象：slide_002.png
```

**ポイント**：1枚ずつ指示するのではなく「対象の関数を修正してください」と指示。関数1か所修正で複数枚に反映される、というテンプレ思考を貫きます。

## 6. トラブルシューティング

| 症状 | 対処 |
|---|---|
| Codexが「フォントが見つからない」と言う | システム標準フォントへフォールバックさせる。`render_slides_reference.py` ではWQY Zen Heiにフォールバック済 |
| 顔写真がアップロードできない | Base64でテキスト化してJSONに埋め込むか、URL指定でCDNから取得させる |
| カードのレイアウトが微妙にズレる | 「絶対座標で指定してください。中央配置の自動計算は避けてください」と追加指示 |
| 文字がワイプエリアに被る | 「テキスト描画前に必ず WIPE_AREA = (1440, 0, 1920, 270) と衝突判定してください」を追加 |
| 色がパレットから外れる | パレットPNGを再度添付＋「HEXコードはこのリストのみ使用可」と再強調 |

## 7. ファイル受け渡し時のチェック（ローカル側）

Codexに渡す前に：

```bash
# 必須ファイル一覧
ls VSL/codex_slide_instructions/
# → UTAGE_VSL_スライド制作指示書_for_Codex.md
# → utage_palette_reference.png
# → 10slides_sample_data.json
# → render_slides_reference.py

# 顔写真フォルダ
ls /tmp/utage_thumbs/
# → 01_kato.jpg 〜 06_konno.jpg

# まとめてZIPにする場合
cd VSL/codex_slide_instructions/
zip -r ../utage_codex_bundle.zip . 
cd ../..
cp -r /tmp/utage_thumbs ./photos_for_codex
zip -r photos_for_codex.zip photos_for_codex/
```
