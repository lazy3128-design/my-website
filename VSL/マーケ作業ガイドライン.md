## このmdの目的

Teruさんからの指摘、教え、よくミスるパターンを実例ベースで記録するもの。  
クロちゃん（Claude）が同じミスを繰り返さないため、また、添削されたものをそのまま理解できるように。

**ここに書いてあることは「0 or 1」ではない。**  
ガイドラインであって絶対ルールではない。  
ケースによっては別のアプローチが正解になる。新しい教えがあれば追記する。

# A. トーン・スタンス

## A-1. UTAGEブランドのトーン

**toBとtoCの中間、ハイブリッド（A寄りのC）**

- toC：寄り添い、感情移入、温度感
- toB：論理、品格、客観性
- UTAGEは**toB寄りのtoC**

### Teruさんの実際の指摘

> 単なるtoC相手の動画なら、僕もそういうふうに感情移入してもらうように作るんだけど、今回は寄り添いすぎると温度感が異なってくる。

> 商材臭が強すぎるのはダメなので、わけわからん限定性とか理想の未来だけ書くとかはダメ。toCとtoBの間ぐらいのテンション感で出していく必要がある。

## A-2. 商材臭を出さない

**避けるべき表現**
- 取って付けた限定性（根拠なき「3日間限定」）
- 過剰な煽り
- 誇張された未来描写
- 情報商材の常套句
- 「驚愕の」「衝撃の」「絶対」など

### 実例：「3日間限定で公開します」だけだと弱い
Teruさんから「**どうして3日間だけの限定公開なんだろう?**」と問われた。
→ 動く理由を明示できない限定性は商材臭の元。

### 実例：「3日ごとに最適化してお届け」のアンチパターン
これを入れると「**3日後に別バージョンを見られる**」=「**今見なくてもいい**」と解釈される。  
緊急性を作ろうとして緊急性を消すパターン。

## A-3. ナレーション型

完全ナレーション型（B-1）、属人性最小、顔出しなし。

# B. ターゲットへの目線

## B-1. 対等な目線を保つ

**NG表現**
- 「頭のいいあなたなら、もうお気づきでしょうか」=上から目線

### Teruさんの実際の指摘

> この表現は馬鹿にしてる感じがあるなぁ...ちょっと目線が↑なんですね。  
> もし僕だったら、「すでにお気づきだと思いますが」とか、表現はちょっと微妙なので考えてほしいけど、テイスト感の参考までに

**OK表現**
- 「すでに、お気づきの方も、いらっしゃるかもしれません」
- 「あなたは、すでに、気づいているはずです」（直接性）

## B-2. 攻めない（一般論として描く）

「あなたはこれをやってる、ダメ」と直接攻めない。  
「**こんな状況に陥ることがある**」「**多くの方がこんな状況に陥っている**」と一般論で描く。

### Teruさんの実際の指摘

> 具体事例は成功した人がやってたことなんだ→自分も同じや...→かわれるかも！このワクワクを出そう

> もともと、事業が停滞してて〇〇の状態から〇〇になった人がいて～～～的なお客様の声をベースに変化を書く、すると、自分が攻められてない感を出せるよね。

## B-3. 「ご自身」「いらっしゃる」の過剰使用回避

**NG**：「ご自身がいらっしゃるかもしれません」連発  
**OK**：「あなた」基調、必要に応じて「ご自身」を補足的に

### Teruさんの実際の指摘

> 丁寧すぎ「多忙すぎて、業務を効率化しなきゃ回らない」。そう、考えていらっしゃいませんか。 → 「そのように考えていませんでしょうか?」のほうがいい

> なっていらっしゃらないでしょうか? → 丁寧すぎ。「なっていませんでしょうか?」ぐらいでOK

### 過剰丁寧の判定基準

以下が連続するか重なると過剰丁寧：
- ご自身
- いらっしゃる、いらっしゃらない
- ていらっしゃる、ていらっしゃらない
- でいらっしゃる
- ご〜になる

### 適度な丁寧さの表現例

- 「考えていませんでしょうか?」
- 「なっていませんでしょうか?」
- 「感じることがあるかもしれません」
- 「お気づきかもしれません」

「**でしょうか?**」「**かもしれません**」レベルが、UTAGEブランドのトーンに合う。

## B-4. 直接的すぎる表現は柔らかく

**NG**：「あなたは、こんなことを、していませんか?」=直球すぎる

### Teruさんの実際の指摘

> あなたは、こんなことを、していませんか? 直接的すぎますね。表現が。

**改善方向**：「こんな状況に陥ることがある」「多くの方が経験している」など、ワンクッション置く。

## B-5. 「個人事業主」などの決めつけNG

ターゲット属性を勝手に限定しない。

### Teruさんの実際の指摘

> 個人事業主が、これらすべての変化に対応するのは、 個人事業主と決めつけなくていいよ。

**改善方向**：「事業を回しながら」「事業を営む方」など、状況描写で広く。

# D. 言葉選び・表現

## D-1. 言い換えるべき言葉

| NG | OK |
|---|---|
| こなす | 処理する |
| 仕組み化 | 仕組みづくり |
| 衰退 | （避ける） |
| 業務効率化を | 業務を効率化 |
| 数倍に | 安定的に拡大 |
| 具体的な方法 | 考え方/仕組み/実現の道筋/今からお伝えする内容 |

### Teruさんの実際の指摘

> 業務をこなす「速度」を上げること。こなすっていう表現じゃないほうがいいね。

> 売上は数倍に → 「売上は安定的に伸ばし、業務に追われない働き方を実現している」みたいな書き方のほうが丁寧じゃない？

> 「業務効率化を」より「業務を効率化」のほうが自然な口語。ターゲットの内なる声としてリアル。

> 具体的な方法って実際になんだろう?言語化したとき適切な表現になってそうですか?何かのノウハウを教えるものですか?

### 「具体的な方法」が問題な理由

「具体的な方法」と言うと、視聴者は：
- ステップバイステップのノウハウを期待
- 自分で実行できるHow-toを期待
- テクニックや手順の伝授を期待

ところが実際に伝えるのが**ツール紹介**や**考え方**だと、**期待値とのギャップ**が生まれて離脱リスクが高まる。

UTAGEのVSLで伝えるのは「**雑務ゼロの考え方**」+「**UTAGEという仕組み**」+「**活用事例**」。  
これはノウハウではないので、「具体的な方法」と表現すると誤解を生む。

### 適切な言い換え

伝える内容に応じて：
- 考え方が中心 → 「**考え方**」「**新しい選択肢**」
- ツール・仕組みが中心 → 「**仕組み**」「**実現のための仕組み**」
- 全体像を見せる → 「**全体像**」「**実現の道筋**」
- 漠然と全体を指す → 「**今からお伝えする内容**」

## D-2. UTAGE設計思想のキーワード

- **「なくす・ゼロにする・自動化」**（時短ではない）
- **「基盤を整える」**
- **「業務ではなく雑務」**=キーフレーズ
- **UTAGEは「オールインワン型ツールとして国内最大級」**（「国内最大級のMA」ではない）

## D-3. 業務→雑務の切り替え

最初は「業務」（中立的）で入り、途中で「雑務」へ切り替える。

### Teruさんの実際の指摘

> 大事なメッセージのところには「業務ではなく雑務」とか使ってもいいしね。まあいきなりだとビックリするから、業務→雑務への切り替え、そこから雑務っていうふうに使うとかもできる。

## D-4. 数字を積極使用

| 数字 | 使い方 |
|---|---|
| 9割、8割 | 「あなたの努力の9割は」（衝撃） |
| 10/30/100人 | 「お客様が10人、30人、100人と増えれば」（具体性） |
| ゼロ | 「雑務をゼロにする」（明確) |
| 3倍 | 「売上3倍」（根拠ある時のみ） |

ただし、数字には**根拠が必要**。根拠ない数字（事例集にない値）は嘘になる。

## D-5. 稚拙語の回避

| NG | OK |
|---|---|
| もっとやる | やるべきこと |
| やらなくてもいい | 手から切り離す |

# E. 文章構造・リズム

## E-1. 「そ」連発を避ける

冒頭の母音を散らす。指示語を減らす。

### Teruさんの実際の指摘

> よく見かけますが、「その」「そして」という「最初の入りの母音が同じ」文章が多く、全体的に指示語が多くて稚拙感を感じます。

**対処**：各スライド冒頭の母音をチェック、「そ」始まりが連続したら言い換える。

## E-2. 指示語は使う時の判断

「0 or 1」ではない。使うことで自然・美しくなるなら使ってOK。

### Teruさんの実際の指摘

> 必要であれば指示語を使ったりするのもいいですよね。だって、使ったら美しい、わかりやすいときは使えばいいので。

## E-3. ぶつ切り感を絶対なくす

スライド間の繋ぎは丁寧に。

### Teruさんの実際の指摘

> シンプルなんだけど、ぶつ切り感は絶対になくしたいです。  
> ここはワンクッション入れてもいい。かったるさを感じない程度に、前後の分脈を考えて必要であれば指示語を使ったりするのもいいですよね。

## E-4. 「だから」連発NG

最後のまとめで1回だけOK。

## E-5. 読点の使い方

### 基本原則
読点が多すぎるとリズムが死ぬ。最小限に。

### カッコの前後には読点を付けない

「」で括った言葉の前後には**読点を付けない**。

### Teruさんの実際の指摘

> カッコで括った文字の前後には読点無しでお願いします

### 例

NG：
```
いわゆる、「雑務」、です。
それらはすべて、「雑務」、なんです。
```

OK：
```
いわゆる「雑務」です。
それらはすべて「雑務」なんです。
```

→ 「」の前後は読点なし。カッコ自体が句切りの役割を果たすので、読点は冗長。

## E-5.5. 文末表現のリズム

### 基本原則

同じ文末表現が連続すると、リズムが死ぬ。  
特に「**〜なんです**」「**〜ないんです**」「**〜のです**」など、強調系の文末が続くと**くどい**印象になる。

### Teruさんの実際の指摘

> 「ないんです」「なんです」この表現があまり続かないように、リズムよく話せるように、体言止めも多く使っていくといいですね。

### 文末表現のバリエーション

| タイプ | 例 |
|---|---|
| 通常の断定 | 〜です、〜ます |
| 強調 | 〜なんです、〜のです |
| 否定強調 | 〜ないんです、〜ではないんです |
| 体言止め | 〜変化、〜状態、〜毎日 |
| 動詞止め | 〜になる、〜していく、〜変わる |
| 問いかけ | 〜でしょうか、〜ませんか |

### リズム作りのテクニック

連続を避けるために、**3〜4文ごとに体言止め**を入れる。

NG（強調系の連発）：
```
〜なんです。〜ないんです。〜のです。
```

→ くどい、押し付けがましい印象。

OK（バリエーション+体言止め）：
```
〜なんです。〜していく毎日。〜変わっていきます。〜なのです。
```

→ リズムが生まれる。

### 体言止めの効果

- リズムを変える
- 余韻を作る
- 印象的に締める
- 押し付けがましさを減らす

### 強調系を使うタイミング

「〜なんです」「〜ないんです」は**ここぞ!**という時だけ。  
連発すると効果が薄れる。

## E-6. 1スライドの文章量・デザイン

### 基本原則

長文は分割、画像化や図式化も検討。  
スライドは**1スライド1メッセージ**を原則とする。

### Teruさんの実際の指摘

> 1枚のスライドにするには 文章がながいところがあります。（箇条書きはOK）

### スライドのタイプ分け

スライドには大きく3タイプある。**混在させない**こと。

#### タイプ①：メッセージ系（1メッセージ集中）
- 1つのメッセージを大きく見せる
- **2行構成が基本**
- 3行構成にする場合は、**1行あたりの文字数を少なめ**にする
- 4行以上は分割を検討
- 強いメッセージ、決め台詞、衝撃の言葉に使う
- 例：「これ以上、◯◯するのは今すぐ止めてください」

### Teruさんの実際の指摘（行数・文字数）

> なるべく2行構成、3行の場合は文字数が少なめが好ましい

### 行数判断の判定例

OK（2行）：
```
雑務をゼロにすることに、
すべてを注いでください。
```

OK（3行・文字数少なめ）：
```
雑務から解放され、
本業に集中し、
事業を拡大していく。
```

NG（3行・文字数多い）：
```
あなたがやらなくてもいい、本業の価値を生まない、
運営上の手作業。
それを、私たちは「雑務」と呼びます。
```

→ 1行目が長すぎる。分割を検討。

#### タイプ②：箇条書き系（箇条書きだけで完結）
- 箇条書きのみで1スライド
- リード文・締めの文を入れない
- 列挙する具体例、運営の実態、未来描写などに使う

#### タイプ③：橋渡し系（短い文+問いかけ）
- 「こんな運営、していませんか?」など
- 箇条書きへの導入に使う場合は、箇条書きと別スライドに分ける

### 分割の判断基準

以下のいずれかに該当したら**分割を検討**：
- メッセージ+箇条書きが同居している
- メッセージが2つ以上ある
- 文章が4行以上
- メッセージ性が強い文に、別の文がくっついている

### 例

NG（混在）：
```
こうした運営に追われ続けると、

朝、メールチェックから1日が始まり、
夜、未対応を残したまま眠る毎日。

✅ 新しい商品の構想を、練る時間がない
✅ コンテンツを、磨く時間が取れない

本来、やるべきことが、おろそかになっていく。
```

→ メッセージ＋情景＋箇条書き＋締め=4要素が1スライドに同居。

OK（分割）：
```
スライドA：
こうした運営に追われ続けると、
朝から夜まで、運営の業務に追われる毎日。

スライドB（箇条書き）：
✅ 新しい商品の構想を、練る時間がない
✅ コンテンツを、磨く時間が取れない
✅ ...

スライドC（メッセージ）：
本来、やるべきことが、
おろそかになっていく。
```

### 同じ箇条書きが増えるのを避ける

同じパターンの箇条書きが連続したら、統合や役割の見直しを検討。

### Teruさんの実際の指摘（箇条書きの分け方）

> 同じような箇条書きが増えているなと思いました。  
> クライアントワーク・受講生などと箇条書きをわけたのってどうしてでしたっけ？

→ 箇条書きを分けるなら、分ける理由が明確である必要がある。

## E-7. スライドとナレーションの役割分担

### 基本原則

スライドとナレーションは**同じことを書かない**。役割を分ける。

- **スライド**：メッセージそのもの。決め台詞、本質、結論。
- **ナレーション**：接続語、補足、流れを作る言葉、追加の説明。

### Teruさんの実際の指摘

> 「だから、まず、」をスライドからカットしてもいいです。ナレーションで言えばいいですからね。「なぜなら」とかも、ナレーションで回収できればOK

### スライドからカットしてOKな言葉

- 接続語：「だから」「なぜなら」「その結果として」「さらに」「ですが」「それなのに」「ところで」
- 補足の前置き：「実は」「おそらく」「ここで」「つまり」
- リード文の冒頭：「これからお伝えする〜」「次に〜」

これらは**ナレーションで言えば伝わる**。スライドに書くと、メッセージそのものが薄まる。

### 例

NG（接続語がスライドに入る）：
```
スライド：
だから、まず、
雑務をゼロにすることに、
すべてを注いでください。
```

→ 「だから」がスライドに入って、メッセージが薄まる。

OK（スライドはメッセージ集中、接続語はナレーションで）：
```
スライド：
雑務をゼロにすることに、
すべてを注いでください。

ナレーション：
だからこそ、まず、雑務をゼロにすることに、すべてを注いでください。
```

→ スライドは強いメッセージだけ。ナレーションで「だからこそ、まず」と前のスライドからの流れを作る。

### 判断ルール

スライドに書く前に問い直す：
- この言葉、**ナレーションだけで伝わるか?**
- 伝わるなら、**スライドからカット**してナレーションに回す
- スライドには**メッセージの核**だけ残す

### 例外：短文で「ここぞ!」の強調時はスライドに残してOK

接続語であっても、以下の場合はスライドに残す価値がある：
- **短文**で、その接続語が**強調効果**を生む時
- 視覚的に「**ここで転換**」を強く印象づけたい時
- メッセージそのものを際立たせる時

つまり「**0 or 1**」ではない。  
**長文の中に埋もれて薄まる接続語**は、ナレーションに回す。  
**短文で接続語そのものに意味を持たせたい時**は、スライドに残す。

### Teruさんの実際の指摘

> 短文で、ここぞ！！！という時はスライドに入れてOK

### 判断の例

NG（長文に埋もれて薄まる）：
```
スライド：
だから、まず、
雑務をゼロにすることに、
すべてを注いでください。
```

→ 「だから」が長文に埋もれて、メッセージが薄まる=ナレーションに回す。

OK①（短文で転換を強調）：
```
スライド：
それなのに。
```

→ 短文で「**ここで転換が起きる**」を強烈に印象づける時はOK。

OK②（メッセージの一部として機能）：
```
スライド：
それなのに、

意図せず、このような運営に、
なっていませんでしょうか?
```

# G. 動機付け（人を動かす理由）の設計

## G-1. 人は理由なく動かない

### Teruさんの実際の指摘

> 人はAIのようにいわれたことを素直にはやりません。  
> 何か、動く理由をつけてあげたり、自発的に動くような仕掛けがないと動かない生き物なのです。

## G-2. ターゲットの脳の処理を最後まで追う

書いた言葉が**逆の動機**を生まないかチェック。

### 実例：「3日ごとに最適化」の罠

「3日ごとに内容を最適化してお届けしています」と書くと：
1. 「あ、3日後にも動画があるんだ」
2. 「じゃあ今のは未完成バージョン?」
3. 「次の方がいいなら、待とう」

→ **緊急性を作ろうとして、緊急性を消した**。

### Teruさんの実際の指摘

> 結局はここに集約されます。だって日数がすぎる事に熱が冷める→かわなくなるでしょ？  
> 考えればちゃんとわかるんだから、ここまで考えて出してほしいなぁ

## G-3. 「待っても意味がない」形で動機を作る

- 時間の機会損失（待つほど自分が損する）
- 損失の連鎖（誤判断でさらに損失拡大）
- 競合の動き（同業者も同じ環境）
- 自分自身の負荷（雑務時間が積み上がる）

## G-4. 伏線を貼るテクニック

大義名分を言う時、伏線を先に用意しておく。

### Teruさんの実際の指摘

> こういうときって、ひとつテクニックがあるんだけど、この大義名分を言うときの伏線を先に用意しておくってのもアリ。

例：事業主が時間損失に後から気づいた、と先に描いておくと、後で「時間が過ぎてくだけ」と言っても自然。

## G-5. 動機付けの種類を区別する

### 基本原則

「動機付け」と言っても、**目的によって種類が異なる**。  
混同すると、間違った動機付けを設計してしまう。

### 動機付けの主な種類

| 種類 | 目的 | 設計 |
|---|---|---|
| **購入の動機付け** | 商品を買わせる | 限定性、緊急性、損失回避（強め） |
| **視聴継続の動機付け** | 動画を最後まで見させる | 「今、後回しにしない理由」を提示（柔らかめ） |
| **行動の動機付け** | 申し込み、登録など特定の行動を促す | 行動の必然性、ベネフィットを明示 |
| **継続の動機付け** | 関係を続けさせる | 信頼の積み重ね、長期価値の提示 |

### Teruさんの実際の指摘

> もし3日間限定というのが合わなければ、今すぐ動画を最後までみる、このまま最後まで動画をみることを伝えてほしいのです。  
> 人は理由がなければ後回しにしますよね?だから、嘘くさくない、スマートな、誰でも納得できる理由を違和感なくつけることで、いま、この瞬間に最後まで動画をみるためのトリガーのような言葉を使いたいだけです。

### フックパートでの動機付けは「視聴継続」

フックパートの目的は「**最後まで見てもらうこと**」。  
ここで「**購入の動機付け**」を入れると、温度感が合わず商材臭が出る。

代わりに「**視聴継続の動機付け**」を設計する：
- 「**今、後回しにしない理由**」を提示
- 「**最後まで見ることで得られる気づき**」を予告
- 「**動画自体の希少性・限定性**」（購入の限定性とは別物）

### 視聴継続トリガーの設計

「**今すぐ最後まで見る理由**」として機能する要素：

1. **動画の限定公開**
   - 「**この動画は◯日間のみ公開**」=動画自体の希少性
   - 「**今だけ視聴可能**」=機会の限定

2. **今後の視聴ハードル**
   - 「**今、まとまった時間が取れているうちに**」
   - 「**次見る時には、忘れてしまう内容**」

3. **続きで得られる価値の予告**
   - 「**最後まで見ることで、◯◯が明確になる**」

4. **中途半端な理解のリスク**
   - 「**途中で止めると、誤った判断につながる**」

### 改善ルール

動機付けを設計する前に、必ず確認：
1. **この動機付けの目的は何か?**（購入?視聴継続?行動?）
2. **目的に合った設計になっているか?**
3. **ターゲットの心理状態（購入意欲のレベル）に合っているか?**

「動機付け＝購入の背中押し」と決めつけない。  
**今、その場面で何をさせたいか**から逆算する。

## H-5. 未来描写には数字+モデルケースの変化量を「さらっと」入れる

### 基本原則

未来描写を抽象的な言葉だけで書くと、説得力が弱い。  
**活用事例（モデルケース）の変化量**を、数字を使って「**さらっと**」入れることで：
- 権威性が出る（実例がある証明）
- 視聴者の脳に具体的な像が浮かぶ
- 「自分にもできるかも」と思える

「**さらっと**」がポイント。**強調しすぎない**、**自慢っぽくしない**。

### Teruさんの実際の指摘

> ここはもう少し数字を使って具体的にしましょうか。  
> 活用事例の声をベースにしていいので、どんな未来になるのか? こういうところで上手にモデルケースの人の変化やその変化量を「さらっと」伝えると権威性に繋がるし、余裕がでます。

### 例

NG（抽象的）：
```
売上は、安定化、そして、右肩上がりへと変わっていきます。
```

→ 抽象的、像が浮かばない、権威性なし。

OK（数字+モデルケースの変化量、さらっと）：
```
売上は、安定化から、右肩上がりへ。
ある活用事例では、月商が2倍、3倍へと、変わっていきました。
```

→ 「2倍、3倍」=具体的な変化量。「ある活用事例では」=モデルケース引用、さらっと。

### 数字の使いどころ

- **時間の削減**：「月10時間→1時間」「週5日作業→2日」
- **売上の変化**：「2倍」「3倍」「月商◯倍」
- **コスト削減**：「ツールコスト50%減」
- **規模の拡大**：「受講生100名→500名」

ただし、**事例集から取った実数値のみ**使用すること（D-4に従う、根拠ない数字はNG）。

### 「さらっと」の表現テクニック

権威性を出しつつ、自慢っぽくしないために：
- 「**ある活用事例では**」「**実践された方の中には**」など、**個別の事例**として提示
- 「**〜という方もいらっしゃいます**」と**含み**を持たせる
- 強い断定は避ける（「全員がそうなる」みたいな表現NG）

# O. UTAGEの本質的な位置づけ

## O-1. UTAGEは「販売の導線」そのもの

UTAGEはツールではなく、**集客から販売、決済、コンテンツ提供、フォローまでの一連の導線そのもの**。

「効率化ツール」と捉えると本質を外す。

### 含意

- 「業務を効率化するツール」と書くと、UTAGEの本質を矮小化する
- UTAGEは**事業の運営の基盤**そのもの
- 「販売の仕組み全体を整える」のがUTAGE
- だから「**仕組みづくり**」「**基盤を整える**」というキーフレーズが効く

### 守り(雑務削減)と攻め(売れる流れ)の関係

UTAGEには2つの側面がある：
- **守り側**：複数ツール統合による雑務削減、運用コスト削減、トラブル耐性
- **攻め側**：ファネル設計、売れる流れの構築、売上の最大化

**両者は対等な価値**であり、どちらか片方だけを描くと本質を外す。  
むしろ、**攻めが主、守りはおまけ**くらいの位置づけ。  
UTAGEは「ファネルそのもの」であり、「販売の流れを作るツール」が本質。

### Teruさんの実際の指摘

> UTAGEはファネルそのものだと認識しておりまして、販売導線を整える仕組みとして多彩な機能があります。売れる流れを作るための。様々なファネルもすぐ使えますしね。

## O-2. UTAGEがやらないこと

集客（広告、SNS、SEO）は扱わない。  
あくまで「**集客した後の販売導線**」が範囲。

## O-3. UTAGEの攻めの機能(売れる流れを作る)

UTAGEは**販売の流れ**を作るための、多彩な攻めの機能を持つ。

### 主な攻めの機能

#### 1. ファネル設計と多彩なテンプレート
- LP → オプトイン → ステップ配信 → セールス → 決済 → アップセル → 会員サイト → 継続フォロー
- これらを**一気通貫で繋げる**ことができる
- 売れるファネルのテンプレートが**すぐに使える**形で揃っている
- フックパートで提示した「雑務ゼロ」の先にある、「**売れる流れを作る**」がここ

#### 2. シナリオ分岐
- お客様の行動(クリック、未読、購入、未購入など)に応じて、配信内容を自動で分岐
- 「全員に同じ内容」ではなく、「一人ひとりに最適な内容」を届ける

#### 3. アップセル・クロスセル
- 購入直後の追加オファー
- LTV(顧客生涯価値)の最大化
- 売上を「点」じゃなく「線」で作る

#### 4. ステップ配信(教育シーケンス)
- 自動でお客様を教育し、購入に至るまでの「流れ」を作る
- メール+LINE両方で同時に運用可能

#### 5. 会員サイトの自動構築
- 購入後の体験を設計
- リテンション(継続)に直結

#### 6. A/Bテスト・効果測定
- LP、件名、配信タイミングなどをテストして改善
- 「売れる流れ」を継続的に最適化

#### 7. アフィリエイト機能
- 既存顧客やパートナーを「紹介者」として活用
- 集客の幅を広げる(集客自体はUTAGEの範囲外だが、仕組みは提供)

### VSLで描くべきこと

UTAGE紹介セクションでは、機能を**列挙だけ**で終わらせない：
- 「**この機能で何ができるか**」
- 「**それによってどんな売れる流れが作れるか**」
- 「**その結果、事業者にどんな変化が起きるか**」

これを、機能ごとに具体的に描く。

### 守りと攻めの両方の事例を出す

事例セクションでは、守り側(雑務削減、時間が戻る)だけでなく、攻め側(売上拡大、ファネル成功)の事例も入れる。

# P. スライド・文章間のつながり（文間文法）

## P-1. 「つながる文は伝わる文」の原則

スライド単体や文単体がよくても、**つなぎ**が悪いと伝わらない。

> 「伝わる」は「つながる」である。  
> 個々のページにどんなに説得力があっても、それらの「つなぎ」部分がスムーズでなければ、聞き手の腹には落ちない。

VSLは特に離脱されやすいため、**つながり**の重要性はプレゼン以上。

## P-2. 文間の浅さ・深さ

- **浅い文間**：滑らかにつながる、書き手の意図が伝わる
- **深い文間**：つながりにくい、読み手が考えなきゃいけない

科学技術文の理論だが、VSLにも応用可能。  
**スライド間**、**ナレーションの文と文の間**にも同じことが言える。

### 浅くする2つの方法

①前文と後文の論理的関係を明確にする  
②適切な接続語を使う

## P-3. スライド切替えの4パターン（ジョブズのプレゼンより）

### パターン1：前置きなしの切り替え
話の流れでサラッと切り替える。スライドが切り替わったことを感じさせない。  
→ VSL転用：自然な流れの中で次の論点に進む時。

### パターン2：番号を述べてからの切り替え
「1つ目」と言ってから切り替える=注目を集めてから見せる。  
→ VSL転用：列挙系。「**3つあります。1つめは...**」

### パターン3：決めセリフと同時に切り替え
キーメッセージを言う瞬間にスライドを切り替える。  
**耳で聴く言葉と目で読む言葉が同じで一緒に飛び込む**=深く染み込む。  
→ VSL転用：核心メッセージ（One Thing「**雑務を、ゼロにする**」など）。

### パターン4：指示代名詞を述べてからの切り替え
「**それが、これです**」「**その結果が、こうです**」と前置きしてから切り替える。  
→ VSL転用：事例を出す時、結果を見せる時。

## P-4. 前スライドの言葉の残像を次に繋ぐ

高度なテクニック。前スライドのキーワードを次のスライドで受ける。

例：
- スライドA：「**事業の成長を止める**のは、思考である」
- スライドB：「では、**事業の成長を止める**思考とは、具体的に何か?」

→ 「事業の成長を止める」のリフレインで連続感が生まれる。

## P-5. セクションの切れ目では「まとめ→橋渡し」を入れる

> 章が変わる際は、前章の内容の「まとめ」を前置きとして、次章のスライドにつなげていくパターンをよく見る。

VSLでも、セクションが変わる時（例：問題提示→解決策、Why→How）には、**前セクションのまとめ**を1スライド入れて橋渡し。

## P-6. 接続語の使い方

| 接続語 | 役割 | VSLでの使用例 |
|---|---|---|
| しかし、ですが、でも | 対比、転換 | ビフォー→アフターの転換 |
| つまり、要するに | まとめ、言い換え | 論点をまとめる時 |
| たとえば、具体的には | 例示 | 一般論から具体事例へ |
| また、さらに | 並列、追加 | 同じ系統の話を追加 |
| なぜなら、というのも | 理由 | 結論の根拠を示す |
| 結果、その結果 | 結論、因果 | 原因→結果 |
| 一方 | 別の話題への転換 | 別の側面を見せる |
| ところで | 話題転換 | （VSLでは使わない方が無難）|
| では、それでは | 次のステップへ | セクション間の橋渡し |

# Q. クロちゃんがミスりがちなアンクルブレイクのパターン

## Q-1. 論理関係なしに次のスライドへ

例：「これ以上は無理だと諦めかけていた」→「もし、この状況に一つでも当てはまるなら」  
→ 急変化。前は事業主の話、後はターゲットへの問いかけ=主語が違うのに繋ぎ語なし。

## Q-2. 接続語の選択ミス

「そして」「その」など、論理関係を曖昧にする接続語を多用。  
→ 「**そして**」=並列だが、何と何を並列してるか曖昧。  
→ より明確な接続語（**結果、つまり、ただし、一方**など）を使うべき。

## Q-3. 前のスライドの言葉を捨てる

前のスライドで「**雑務**」と言ったのに、次のスライドで急に別の言葉を使う。  
→ リフレインで繋ぐべきところを捨ててる。

## Q-4. 論理破綻

「**必ず物理的限界が訪れます**」→「**多くの方が陥ることがあります**」  
→ 断定の後で不確定の表現=破綻。  
構造変更時は、後続スライドの整合性を必ず確認。

## Q-5. 章の切れ目で唐突に転換

Why（理論）→事例（権威）に切り替わる時に、橋渡しなし。  
→ 「**ここで、実際の例を見てみましょう**」みたいな前置きが必要。

# R. 直接表現を避け、「伝わる表現」で書く

## R-1. 直接的な言葉は既視感を生む

直接的な表現は、ターゲットの脳に**既視感**を生む。  
「忙しい」「追われる」「諦める」「成長する」=どこかで読んだ表現。  
→ 響かない、刺さらない、流される。

### Teruさんの実際の指摘

> 直接的な言葉ではなく、それを伝える表現で「伝わる」台本を書くことが大事なんだ。  
> なぜなら、直接的な表現は既に既視感があるから。

## R-2. 観察眼+語彙力で表現する

優れた書き手は、**他人を観察し、その行動・反応で感情を描く**。

→ VSL転用：ターゲットの**振る舞い**を描く。

例：
- 直接：「あなたは忙しすぎる」
- 表現：「朝起きて最初に開くのはLINE。返信していたら、もう昼。」

## R-3. 「感情」を「反応」で描く

感情を直接書かず、**体の反応・心の反応**で描く。

### 例：「疲れている」を描き分ける

- 体の反応：「目を擦りながらPCを開く」「肩が上がらない」「気がつくと夜中」
- 心の反応：「もう何もしたくない」「これ何のためにやってるんだろう」

### 例：「焦り」を描き分ける

- 「未読の通知が、また増えている」
- 「画面を閉じても、頭から離れない」
- 「『あれ、まだやってなかった』が口癖になっている」

## R-4. レベルと種類で描き分ける

> 「怒り」という感情のなかには、激昂するのか、地団駄を踏むのか、イラッとするのか、怒鳴り散らすのか、じつにさまざまなレベルの「怒り」が存在します。

VSLで頻出する感情も、同じく描き分ける必要がある。

### 「疲弊」のバリエーション
- ぐったり、疲労困憊、燃え尽きる、麻痺している、気力が削られる、消耗、限界

### 「諦め」のバリエーション
- 諦めかける、心が折れる、もういいや、この働き方を続けるしかない、思考停止

### 「忙しい」のバリエーション
- 追われる、手が回らない、目が回る、息つく暇もない、寝る間も惜しい

## R-5. 情景・状況で雰囲気を作る

直接的な感情語じゃなく、**情景**で雰囲気を作る。

### 例：「焦り・追われている感」を情景で

- 「朝、コーヒーを淹れる間も惜しんでPCを開く」
- 「画面の通知バッジが、今日も二桁を超えている」
- 「気がつけば、窓の外は暗くなっている」

## R-6. ビフォーとの対比でドラマ性を作る

> 書き手の立場で注意したいのは、読者にとって「滑らか」な状態は楽しくないということ。波乱もトラブルもなければ、手に汗握るドラマ性が期待できないからです。

→ 未来描写で「すべて順調」と書くだけだとつまらない。  
→ **ビフォーとの対比**で見せる。

例：
- 「朝、メールチェックから1日が始まっていた毎日が、今では、新しい商品の構想を練ることから始まる。」

## R-7. 主語を「人」にすると非難になる

### 基本原則

「**人が〇〇**」「**人は〇〇**」と人物を主語にすると、ターゲット個人に**矢が向く**ことがある。  
特に「**変わる**」「**動く**」など、行動や状態変化を語る時、主語が「人」だと「**あなたが変わらないとダメ**」と非難されているように感じられる可能性。

代わりに**事業、状況、結果**などを主語にすれば、ターゲット個人を批判せず、変化の必要性を伝えられる。

### Teruさんの実際の指摘

> 人が変わるって言ってしまうと、あなたに非があるのではないか?と取られてしまう可能性がありますので、もう少し違う表現を使いましょう。  
> 人が変わるではなく、事業がより良い方向に動き出すには〜とか、特定の人物を批判しないような方向性で、かつ、今すぐ変えたほうがいいよねと思ってもらえるような感じで

### 例

NG（人を主語にして非難になる）：
```
人が変わるのは、知識を得た瞬間ではなく、理解が深く腑に落ちた瞬間です。
```

→ 「**人が変わる**」=ターゲットに矢が向く。「変わってないあなたが悪い」に聞こえる。

OK（事業・状況を主語にして批判しない）：
```
事業が、より良い方向に動き出すのは、
情報を知った瞬間ではなく、
その情報が、深く腑に落ちた瞬間です。
```

→ 主語が「**事業**」になることで、ターゲット個人ではなく**事業の動き**に焦点。  
→ 「**事業のために、いま行動する価値がある**」と感じられる。

### 改善ルール

「人」を主語にする前に確認：
1. その主語、ターゲット個人を**指してしまっていないか?**
2. **批判**に聞こえる可能性は?
3. 「**事業**」「**状況**」「**結果**」など、別の主語に置き換えられないか?

### 関連セクション
- B-2（攻めない、共感ベース）
- I-1（あなたのせいじゃない、直接書かない）
- C-2（ターゲットの実態を決めつけない）

## R-8. 人物紹介で「他人行儀」にならない

### 基本原則

ナレーション形式や説明的な文章で人物を紹介する時、「**〇〇という人物**」「**〇〇という方**」など、**距離感のある修飾語**を使うと、不自然に他人行儀になり、紹介された人物が遠く感じられる。  
特に、語り手が中立的ナレーターである時に、紹介される人物への距離が過剰に出ると、視聴者は「**誰がこの人を語っているんだろう**」と気になり、内容に集中できなくなる。

### 起きやすい場面

- 開発者、創業者、講師など、特定の人物を紹介する時
- 「事実だけ伝える」という意識で、修飾を加えすぎる時
- 視聴者と紹介される人物の間に、ナレーターという第三者が挟まる時

### 例

NG（他人行儀）：
```
このUTAGEを開発したのは、いずみゆう、という人物です。
```
→ 「**という人物**」が距離を作る。観察者ポジションが強すぎる。

NG（同じく他人行儀）：
```
UTAGE開発者の、想いを、お伝えします。
```
→ 「**開発者の**」が抽象的すぎて、具体性が薄れる。

OK（人物として位置付ける）：
```
このUTAGEを開発したのは、こちらの人物です。
（次のスライドで）いずみゆう。株式会社Fountain代表取締役で、UTAGEの開発者です。
```
→ 「こちらの人物」+ 顔写真 + 名前と肩書きを別スライドで提示。自然な紹介の流れ。

OK（本人発の言葉として伝える）：
```
UTAGE開発者である、いずみから、その実装にいたった想いを、お伝えします。
```
→ 「**いずみから**」=固有名詞を使う+「**実装にいたった想い**」=具体性を加える。
本人発の言葉として伝わる。

### Teruさんの実際の指摘

> いずみゆうという人物～みたいな言い方だとめちゃくちゃ他人行儀なので、なんかそこら辺の言い回しをうまくしたい

> UTAGE開発者の、想いを、お伝えします。→UTAGE開発者である、いずみから、その実装にいたった想いをお伝えします。みたいなナレーションの方が自然な気がしますね。

### 改善ルール

人物紹介や、ある人物の想い・発言を伝える時：
1. 「**〜という人物**」「**〜という方**」など、距離感のある表現は避ける
2. **固有名詞**（名前）を可能な限り使う
3. **抽象的な属性**（「開発者の」「代表の」）より、**具体的な人物**（「いずみから」「〇〇さんから」）を主語にする
4. 想いや発言を伝える時、**何にいたった想いか**を具体的に描く（例：「実装にいたった想い」「設立にいたった想い」）

### 関連セクション
- S-21（冷静と無機質を取り違える）

## S-1. 抽象語を組み合わせただけで満足する

### 問題の本質

「ビジネスっぽい言葉」「カッコいい言葉」を組み合わせると、書いた本人は伝わったような気がする。  
だが、抽象語同士の組み合わせは、読み手の脳に**像が浮かばない**。

### 起きやすい場面

- 抽象的なメッセージを書く時（解決方向の提示、未来描写、価値訴求など）
- 「ビジネス書的な言葉」で書こうとする時
- 短くまとめようとして抽象度を上げてしまう時

### 例

抽象語の組み合わせ（NG）：
- 「シンプルに事業を回せる仕組み」
- 「効率的なソリューション」
- 「最適な運用」

→ 「シンプル」「回す」「効率的」「ソリューション」「最適」「運用」=すべて抽象語。組み合わせても具体性は生まれない。  
読み手は「**何のこと?**」となる。

具体的な表現（OK）：
- 「申込みから決済、会員サイト案内まで、一つの画面で完結する」
- 「メールもLINEも、同じシステムから送れる」

### 改善ルール

抽象語を使う時、自分で「**これって具体的に何?**」と問い直す。  
問い直して**具体的な動作・状態・現象が答えられない**なら、その言葉は使わない。  
または、具体例を**直後に補足**する。

### 関連セクション
- R-1（直接的な言葉は既視感を生む）
- R-2（観察眼+語彙力で表現する）

## S-2. 自分の頭の中の繋がりと、読み手の脳の繋がりを混同する

### 問題の本質

書き手は文章全体の流れ・伏線・狙いを把握している。だから自分が読み返すと、すべてが繋がって見える。  
だが、初めて読む人は前後の文脈を知らない。書き手が「自然な繋がり」だと思っているものが、読み手には**唐突**に感じられる。

### 起きやすい場面

- 伏線を仕込んだ時
- セクションをまたぐ時
- 構造変更で順序を入れ替えた時
- 慣れた文章を何度も推敲した時（書き手の脳が文章に最適化されてしまう）

### 例

書き手の脳内：「Aで『新しい方向性』とほのめかし→Bでその方向性を具体化→Cでさらに展開」=完璧な伏線回収  
読み手の脳：「Aの『新しい方向性』とBの内容が結びつかない=唐突」

### 改善ルール

書いた後、**初めて読む人の脳**でその論理が繋がるか検証する。  
具体的には、各文・各スライド単独で読んだ時に、**前のスライドからの論理的な必然性**が見えるかチェック。

「**自分が知ってる文脈を抜きにしても、繋がっているか?**」を問い直す。

### 関連セクション
- P-1（つながる文は伝わる文）
- P-2（文間の浅さ・深さ）
- Q（アンクルブレイクのパターン）

## S-3. 個別の言葉の良し悪しだけで判断し、文章全体の中での役割を見ない

### 問題の本質

言葉一つひとつを「自然な日本語か」「ビジネスっぽいか」だけで判断すると、文章全体の流れの中で**機能しない言葉**を選んでしまう。  
言葉は**文章の中でどう働くか**で評価すべき。

### 起きやすい場面

- 単語レベルで言い換えを検討する時
- 同義語の中から選ぶ時
- 「自然な日本語かどうか」だけを基準にする時

### 例

ある言葉が「単体としては自然な日本語」でも：
- そのスライドが**問いかけ**で終わるなら、問いかけと相性のいい言葉を選ぶ
- そのスライドが**結論**を提示するなら、断定的な言葉を選ぶ
- 前後のスライドのトーンと**一致するか**を確認する

複数の同義語（例：「働き方」「運営」「やり方」）=どれも自然な日本語だが、文脈によって最適解が変わる。

### 改善ルール

言葉を選ぶ時、必ず確認：
1. このスライド・文の**機能**は何か?（問いかけ?描写?結論?橋渡し?）
2. 周辺の**トーン**と一致するか?
3. 続きへの**繋がり**は自然か?

個別の言葉の良し悪しではなく、**文章全体の中での役割**で判断する。

## S-4. 第三者視点の分類を持ち込む

### 問題の本質

ターゲット向けの文章なのに、「**分かりやすく分類しよう**」として、**書き手視点の分類**を持ち込んでしまう。  
ターゲットからすると、自分が分析・分類されている感覚になり、距離感が生まれる。

### 起きやすい場面

- 情報量が多い時、分かりやすくするために見出しをつける時
- ターゲットの多様性をカバーしようとする時
- 整理・体系化したい欲求が出る時

### 例

NG（第三者視点の分類）：
```
【カテゴリA】
✅ 〜
✅ 〜

【カテゴリB】
✅ 〜
✅ 〜
```

→ ターゲットは「**自分はどっち?**」と一瞬考える=距離が生まれる。

OK（ターゲット視点）：
```
こんなこと、していませんか?
✅ 〜
✅ 〜
✅ 〜
```

→ 対象は**あなた**。分類は不要。

### 改善ルール

スライド・文章を書く前に確認：
- **これは誰のためのスライドか?**
- **視聴者のためなら、視聴者の視点で書けてるか?**

第三者視点の分類・見出し・カテゴリは、視聴者を**観察対象**にしてしまう。  
ターゲットを主語にした文章を貫く。

### 関連セクション
- B-2（攻めない、一般論として描く）
- B-4（直接的すぎる表現は柔らかく）

## S-5. ざっくり→具体の流れを飛ばして、いきなり具体に入る

### 問題の本質

具体例の箇条書きをいきなり提示すると、読み手は「**何を見せられているのか**」が分からない。  
要約・問いかけで**枠**を作ってから具体に入ると、読み手の脳が受け入れやすくなる。

### 起きやすい場面

- 説明・列挙パートを書く時
- 事例を提示する時
- 箇条書きで情報を伝える時

### 例

NG（いきなり具体）：
```
✅ Aをやる
✅ Bを管理する
✅ Cで連携する
```

→ 読み手は「**何の話?**」となる。

OK（要約・問いかけ→具体）：
```
こんなこと、していませんか?

✅ Aをやる
✅ Bを管理する
✅ Cで連携する
```

→ 要約・問いかけで枠を作ってから具体に入る。

### 改善ルール

箇条書きや具体例の前に、必ず**1行の要約・問いかけ**を入れる。
- 要約：「これから何を見せるか」
- 問いかけ：「これに心当たりがあるか」

## S-6. 前後の繋がりを意識せず、スライド・文を単体で完結させる

### 問題の本質

各スライド・各文を**単体で完結**させると、隣り合うスライド・文の間に**ぶつ切り感**が生まれる。  
理論として「つながりが大事」と知っていても、書く時に**前を見ずに書き始める**と実装できない。

### 起きやすい場面

- 一気に書き上げようとする時
- 新しいスライド・文を書き始める時
- 構造変更で順序を入れ替えた後

### 改善ルール

新しいスライド・文を書く時、必ずこの順序で：
1. **前のスライド・文の最後**を確認
2. 前の**論理的な帰結**または**最後のキーワード**を確認
3. それを**受ける形**で、新スライド・文の冒頭を書く

各スライドの冒頭は、**前のスライドの最後の語**または**論理を受ける接続語**で始める。

### 関連セクション
- P-4（前スライドの言葉の残像を次に繋ぐ）
- P-6（接続語の使い方）
- Q（アンクルブレイクのパターン）

## S-7. 丁寧さを優先して、主体を曖昧にする

### 問題の本質

「丁寧に書こう」として伝聞表現・婉曲表現を使うと、**誰の話か曖昧**になる。  
読み手が「**ん?ダレの話?**」と一瞬考える=離脱リスク。

### 起きやすい場面

- 事例・他者の話を語る時
- 断定を避けたい時
- 丁寧さを追求する時

### 例

NG（曖昧）：
- 「〜だったそうです」（伝聞）
- 「〜らしいです」（伝聞）
- 「〜のようです」（推量）

→ 主体が誰か、何の話か曖昧になる。

OK（明確な断定）：
- 「〜でした」
- 「〜です」
- 「〜されています」（受動の柔らかい断定）

### 改善ルール

丁寧さより、**主体の明確さ**を優先する。  
柔らかさが必要なら、**丁寧な断定形**で書く。  
主体を曖昧にする伝聞・推量表現は避ける。

## S-8. 構造を完成させることが目的化して、各要素の比重を見失う

### 問題の本質

「ビフォーアフター構造を作らなきゃ」「権威性を提示しなきゃ」など、**構造を完成させる**ことに執着すると、各セクションの**目的に対する比重**を見失う。  
構造のために必要以上に膨らませると、ダレる・テンポが落ちる・本来の目的が達成できなくなる。

### 起きやすい場面

- 推奨される構造（フレームワーク）を実装する時
- 「あるべき形」を意識する時
- 完成度を追求する時

### 例

セクションXの目的：「**最後まで見てもらうこと**」  
そのために必要：内容のほのめかし程度  
やってしまうこと：詳細を複数スライドに展開（構造のため）  
結果：ダレる、本来の目的（最後まで見てもらう）が達成できなくなる

### 改善ルール

書き始める前に、必ず確認：
- **そのセクション全体の目的**は何か?
- **そのセクションの各要素の役割**は何か?
- 目的に対して、各要素の**比重は適切か**?

目的に対して比重が大きすぎる箇所は削る。  
**構造を完成させる**より、**目的を達成する**を優先する。

## S-9. 衝撃の言葉を出した直後に、根拠（Why）を提示しない

### 問題の本質

「衝撃の言葉」「常識を覆すメッセージ」を出した瞬間、読み手の脳は「**なぜ?**」で止まる。  
その「なぜ?」に答えないまま次の話題に進むと、読み手は**置き去り**になる。  
書き手は「Whyは後で出てくる」と知っているから問題ないと感じるが、読み手は知らない。

### 起きやすい場面

- フックで強い言葉・衝撃の主張を出した時
- 常識を否定する主張をした時
- 「実は〜です」と意外な事実を提示した時
- 「あなたの〜が問題」と指摘した時

### 例

NG：
```
スライドA：「あなたの努力は、事業の成長を止めている」（衝撃）
スライドB：「ここ数年で、環境は劇的に変わりました」（環境変化の話）
スライドC：「そもそも効率化とは...」（ようやくWhy）
```

→ スライドAで「**なぜ?**」と引っかかった視聴者が、スライドBで答えを求めても見つからない=置き去り。

OK：
```
スライドA：「あなたの努力は、事業の成長を止めている」（衝撃）
スライドB：「なぜなら、効率化とは...」（直後にWhy）
スライドC：「ここ数年で、環境は変わりました」（背景に進む）
```

→ 衝撃→根拠→背景、の順序。納得感が積み上がる。

### 改善ルール

衝撃の主張・意外な事実・常識を覆すメッセージを出した直後は、**Whyを必ず提示する**。  
「Whyは後で出すから大丈夫」は書き手の都合。読み手の脳は**直後に答えを求める**。

書き手は、衝撃の言葉を出した瞬間、「**読み手の脳に『なぜ?』が浮かんだ**」と仮定して、その答えを次のスライドに置く。

### 関連セクション
- S-2（自分の脳と読み手の脳の混同）
- P-1（つながる文は伝わる文）

## S-10. 構造のテンプレートを、直前の文脈を見ずに当てはめる

### 問題の本質

「マクロ→ミクロ」「背景→ターゲット→Why」「導入→展開→結論」など、書き手の中に**無意識のテンプレート**がある。  
このテンプレートは便利だが、**そのテンプレートが今の文脈で機能するか**を確認せずに当てはめると、読み手の体験を壊す。

特に、直前のスライド・文で読み手の脳がどう動いているかを考えずに「次はこのパターン」と進めると、文脈が断絶する。

### 起きやすい場面

- 慣れた構造（推奨フレームワーク）を実装する時
- 「マクロからミクロへ」など定石を当てはめる時
- セクションを書き始める時、無意識にテンプレートに乗る時

### 例

書き手の頭：
- 「外的要因（マクロ）→ターゲットの状況（ミクロ）」が定石
- だからフックでも、まず環境変化を語ろう

読み手の脳：
- 直前のスライドで衝撃を受けた
- その衝撃の根拠を求めている
- なのに、いきなり環境変化の話が始まる
- 「**え、今の衝撃はどうなったの?**」と置き去り

### 改善ルール

構造のテンプレートを使う前に、必ず確認：
1. **直前のスライド・文で、読み手の脳に何が浮かんでいるか?**
2. **読み手の脳が次に求めるものは何か?**
3. **そのテンプレートは、読み手の求めるものに応えているか?**

テンプレートは「**一般的な流れ**」を示すだけ。  
**今の文脈**で機能するかは、毎回確認する必要がある。

### 関連セクション
- S-2（自分の脳と読み手の脳の混同）
- S-9（衝撃の直後にWhyを出さない）

## S-11. 「何をするか（What）」だけ考えて、「どの順序でやるか（Order）」を考えない

### 問題の本質

複数の要素・解決策を提示する時、それらが**並列**なのか**順序のあるステップ**なのかを区別せずに並べてしまう。  
並列で並べると、読み手は「**どれを優先すべきか**」が分からない=行動できない。  
本来、順序があるなら「**まず〇〇→次に〇〇→最後に〇〇**」と段階で示すべき。

### 起きやすい場面

- 複数の未来描写を列挙する時
- 解決策を並べる時
- メリットを列挙する時
- 「これもできる、あれもできる」と展開する時

### 例

NG（並列で並べる）：
```
雑務をゼロにすると：
✅ 本業に集中できる
✅ 売上が伸びる
✅ クライアントに価値を提供できる
✅ 組織化できる
```

→ 読み手：「全部いいけど、どこから手をつければいいの?」

OK（順序のあるステップ）：
```
ステップ1：まず雑務をゼロにする（直近の悩みを解消）
　↓
ステップ2：販売の導線を整える（売上を最大化）
　↓
ステップ3：仕組みを組織で展開する（事業を拡大）
```

→ 読み手：「順序が分かった。まずステップ1から取り組めばいい」

### 改善ルール

複数の要素を提示する前に、必ず確認：
1. これらは**並列**か?それとも**順序のあるステップ**か?
2. 順序があるなら、**ターゲットの直近の悩み**から始まる順序になっているか?
3. 各ステップの**繋がり**は明確か?（前のステップが、次のステップの土台になるか?）

並列で並べる方が楽だが、**順序で示す方がターゲットの行動を喚起する**。

### 関連セクション
- F-2（One Thing：やることは1つ）
- S-8（構造の目的化）

## S-12. 読み手の「気づき」「衝撃」「納得」の直後に、答えではなく別の話題（警告など）を出す

### 問題の本質

読み手が「気づいた瞬間」「衝撃を受けた瞬間」「納得した瞬間」=その直後、読み手の脳は**次に何かを求めている**。  
そのタイミングで答えを出さず、別の話題（警告、注意、補足）を出すと、読み手は「**え?**」となる。

S-9は「衝撃の直後にWhy」だが、これは「衝撃」「気づき」「納得」すべてに広がる原則。

### 起きやすい場面

- 読み手が問題に気づいた直後
- 読み手が新しい概念を受け入れた直後
- 読み手が「あ、これだ」と感じた直後
- 読み手が「自分の今までが間違ってた」と理解した直後

### 例

NG（気づき→警告）：
```
スライドA：「それらは雑務だ」（気づき）
スライドB：「ですが、解決の順序を間違えてはいけません」（警告）
```

→ 視聴者：「**え、まだ解決策聞いてないのに、いきなり順序の警告?**」  
→ 「気づき→次に何?」に答えていない。警告を先に出してしまった。

OK（気づき→解決策→順序の話）：
```
スライドA：「それらは雑務だ」（気づき）
スライドB：「だから、まず、その雑務をゼロにすることに、すべてを注ぐ」（解決策・One Thing）
スライドC：「その結果として、〇〇」（結果の展開）
```

→ 気づきの後、視聴者が求める「**じゃあどうすればいい?**」に直接答える。

### 改善ルール

読み手が何かを「気づいた」「受け入れた」「納得した」直後は、必ず**読み手の脳が次に求めるもの**を想像する。

問いかけ：
- 気づいた後、読み手は何を求めているか?
- 「**じゃあどうすれば?**」を求めているなら、答え（解決策）を出す
- 「**もっと詳しく**」を求めているなら、詳細を出す
- 「**なぜ?**」を求めているなら、根拠を出す

警告・注意・補足は、答えを出した**後**に置く。

### 関連セクション
- S-2（自分の脳と読み手の脳の混同）
- S-9（衝撃の直後にWhyを出さない）

## S-13. 「順序のあるステップ」を、並列のリストとして見せてしまう

### 問題の本質

「順序があるんだから、順序で並べればいい」と考えて、ステップ1、ステップ2、ステップ3を**箇条書きで列挙**してしまう。  
だが、これは見た目は順序でも、**機能としては並列**。読み手は「**3つのリストがある**」としか感じない。

本当の「順序」は、**因果の連鎖**として描くべき：
- まず〇〇に**すべてを注ぐ**（One Thing）
- その**結果として**、自然に〇〇が起こる
- さらに**その結果として**、〇〇への準備が整う

「**結果として**」「**その上で**」「**それによって初めて**」など、**因果を繋ぐ言葉**で連鎖を見せる。

### 起きやすい場面

- 3ステップを提示する時
- 順序のある未来描写をする時
- 「まず〇〇→次に〇〇」とリスト化したくなる時

### 例

NG（並列リスト的）：
```
✅ ステップ1：雑務をゼロにする
✅ ステップ2：販売の導線を整える
✅ ステップ3：事業拡大への準備をする
```

→ 視覚的には順序だが、3つが**独立した項目**に見える=並列の印象。

OK（因果の連鎖）：
```
まず、雑務をゼロにすることに、すべてを注ぐ。
　↓ その結果として
販売の導線が整い、売上が最大化する。
　↓ さらにその上で
事業拡大への、準備が整っていく。
```

→ 因果の連鎖で繋がる。ステップ1が**唯一今やるべきこと**で、2と3は**結果として起こる未来**だと分かる。

### 改善ルール

「順序のあるステップ」を提示する時、必ず確認：
1. ステップ1とステップ2は**因果で繋がっているか**?（ステップ1の結果としてステップ2が起こる?）
2. **今、やるべきこと**は1つに絞られているか?（One Thing）
3. ステップ2、3は**未来の結果**として描けているか?

並列リストで見せると、読み手は「**3つを全部やる必要がある**」と感じて圧倒される。  
因果の連鎖で見せると、読み手は「**まず1つに集中すればいい、残りは結果として起こる**」と感じて行動しやすい。

### 関連セクション
- S-11（並列と順序の混同）
- F-2（One Thing：やることは1つ）

## S-14. ラベル・カテゴリ語を使うなら、定義を先に置く

### 問題の本質

「雑務」「本業」「仕組み」「導線」など、**ラベル**として機能する言葉を使う時、その**定義を先に置かない**まま使うと：
- 読み手は「**何を指してるんだろう?**」と曖昧なまま進む
- 後でラベルが指すものを示すと、**矛盾**が紛れ込む可能性が高い
- ラベルの**境界**が曖昧になり、ラベルが指すべきでないものまで含めてしまう

書き手は頭の中で「**雑務とはこういうもの**」と思っているから、項目を列挙する時に「**これは雑務**」と判断できる。  
だが読み手は定義を知らないから、列挙された項目を見ても**判断できない**。

### 起きやすい場面

- 専門用語・概念を提示する時
- 「これは○○です」と定義する前に、具体例を列挙する時
- カテゴリ分けして整理する時
- 「○○じゃない」と否定する時

### 例

NG（定義が後）：
```
スライド10：✅ 個別相談のリマインド ✅ 進捗管理 ✅ ...
スライド12：✅ 集客の仕組み構築 ✅ 成果集計 ✅ 案件管理 ✅ ...
（中略）
スライド19：それらはすべて「雑務」なんです。
```

→ スライド12の「集客の仕組み構築」「案件管理」は本来**雑務じゃない**かもしれない。  
→ 後で「雑務だ」と言われると、矛盾が生まれる。

OK（定義が先、または定義しないなら**雑務**を使わない）：
```
スライドA：あなたの手から離せる作業＝雑務、と定義します
スライドB：✅ 個別相談のリマインド ✅ 進捗管理 ✅ ...（雑務の例）
スライドC：これらすべて、雑務として手放すことができます
```

または：

```
スライドA：✅ 個別相談のリマインド ✅ 進捗管理 ✅ ...（運営の実態）
スライドB：気づいてますか?これらの作業に時間を取られて、本業がおろそかになっていることに
スライドC：あなたがやるべき仕事ではない＝雑務です（ここで定義）
スライドD：（雑務であることが確定した項目だけを取り上げて）これらが時間を奪っている
```

→ 列挙した項目の**全部を「雑務」と断定する**のではなく、**雑務に該当するもの**を絞り込む構造。

### 改善ルール

ラベル・カテゴリ語を使う前に確認：
1. **そのラベルの定義は先に置かれているか?**
2. **列挙する項目すべてが、そのラベルに該当するか?**
3. **該当しない項目が混ざってないか?**

定義を先に置けないなら、ラベルそのものを使わず、**状況描写**で代用する。

### 例外：ターゲットの既知の言葉なら定義不要

ラベルが**ターゲットがすでに認識している言葉**（業界用語、一般的なビジネス用語、社会的に流通している言葉）なら、**改めて定義する必要はない**。  
定義を宣言すると、**上から目線**になったり、**冗長**になる。

判断基準：
- ターゲットが日常的に使う言葉か?
- ターゲットが「**ああ、あれね**」と即座に理解できるか?

該当する場合は、**状況描写の中で自然に**そのラベルを使う。  
「**これを〇〇と呼びます**」という定義宣言は不要。

### 例

NG（既知の言葉を定義する）：
```
本業の価値を生まない、運営上の手作業。
これを「雑務」と呼びます。
```

→ ターゲットが「雑務」を既に知っている場合、定義は冗長。

OK（状況描写の中で自然に使う）：
```
事業を回す中で、どうしても出てきてしまう、
本業の価値を生まない手作業。

いわゆる、「雑務」です。
```

→ 状況描写で「雑務」と認識を確認するだけ。定義はしない。

> どうしてもでてきてしまう運営上の手作業＝雑務を～～～みたいなアプローチがいい

## S-15. 関連するメッセージを律儀に分けすぎて、冗長な連続スライドにする

### 問題の本質

「気づき→解決策→Why」のような流れを、**律儀に1つずつスライドに分ける**と、冗長で押し付けがましくなる。  
これらは**1つの転換メッセージ**として圧縮できる場合が多い。  

「**中途半端な〇〇ではなく、〇〇へ転換**」のような**対比構造**で書けば、気づき・解決策・転換を**1スライドで全部伝えられる**。

### 起きやすい場面

- 論理を丁寧に展開しようとする時
- 「気づき」「解決策」「理由」を分けて説明する時
- フレームワーク的に1ステップずつスライド化する時

### 例

NG（律儀に3スライド）：
```
スライドA：おそらく、あなたも気づいているはずです。
スライドB：だから、雑務をゼロにすることに、すべてを注いでください。
スライドC：なぜなら、本業に集中できる時間が、戻ってくるからです。
```

→ メッセージが3つに分散してくどい。

OK（対比構造で1スライドに圧縮）：
```
スライド：
中途半端な「効率化」ではなく、
「雑務ゼロ」へ転換しよう。
```

→ 1スライドで「**今までの方向性NG**」+「**新しい方向性OK**」を同時に提示。  
→ 気づき・解決策・転換が**全部含まれる**。

### 改善ルール

連続スライドを書く時、必ず確認：
1. これらのメッセージは**律儀に分ける必要があるか?**
2. **1つの転換メッセージ**にまとめられないか?
3. **対比構造**（〇〇ではなく〇〇）で書けないか?

メッセージを分けると**丁寧に見える**が、視聴者には**冗長**になる。  
**1スライドで複数の機能**を果たすメッセージが書けるなら、その方が伝わる。

## S-16. 結果（数字・成果）を提示する前に、その結果に至るプロセス（仕組み・方法）を示さない

### 問題の本質

「**こんな結果になります**」と数字や成果を**断定**する前に、その**結果に至るプロセス**（何によって・どうやって）を示していないと、視聴者の脳に「**え、なんで?**」「**どうやって?**」が浮かぶ。

特に**インパクトの大きい数字**（年収10倍、月商◯千万円など）を出す時、プロセスの説明がないと：
- 「**この数字、信じていいの?**」と疑念が生まれる
- 「**自分には無理だ**」と距離を感じる
- ミスリードや誇大広告に見える

### 起きやすい場面

- モデルケースの数字を引用する時
- 未来描写で大きな成果を提示する時
- 「こうなります」と断定する時

### 例

NG（プロセス抜きで結果断定）：
```
スライドA：雑務がゼロになれば、本業に集中できる時間が戻る
スライドB：月40時間削減、ROAS200%、年収10倍
```

→ 視聴者：「**時間ができただけで、なんでROAS200%になるの?**」  
→ 因果が見えない=説得力なし。

OK（プロセス→結果）：
```
スライドA：雑務がゼロになり、本業に集中できる
スライドB：その時間で、〇〇という仕組みを構築できる
スライドC：その結果、月40時間削減、ROAS200%、年収10倍といった変化が
```

→ 「**ある仕組みを持つ**」「**それを使って〇〇する**」という**プロセス**が間にあるから、結果が納得できる。

### Teruさんの実際の指摘

> ある仕組みを持つことで〇〇になったっていう部分がないのに、いきなり上記のように説明するからダメ

### 改善ルール

数字や成果を提示する前に、必ず確認：
1. その**結果に至るプロセス**は、明示されているか?
2. 「**何によって**」「**どうやって**」が見えるか?
3. 視聴者の脳に「**え、なんで?**」が浮かばないか?

プロセスを示せないなら、**結果の数字をぼかす**（「事業者の中には〜という方も」など含みを持たせる）か、**プロセスを先に提示する**。

### 関連セクション

- S-12（気づきの後に答え）
- H-5（モデルケースの変化量をさらっと）

## S-17. 参考素材を借用する時、その素材が機能する文脈ごと確認しない

### 問題の本質

他事例（参考VSL、競合の表現、書籍のテクニックなど）から**テクニックや表現を借用**する時、そのテクニックが**機能している文脈**を確認しないまま、自分の制作物に持ち込んでしまう。

同じテクニックでも、**ターゲットの流入経路・心理状態・購入意欲**が違えば、機能しないどころか**逆効果**になる。

### 起きやすい場面

- 参考VSLや競合の動画から表現を借りる時
- 「このテクニック、効果ありそう」と感じた時
- フレームワークやテンプレートを適用する時
- 「成功事例の真似をすれば成功する」と考える時

### 文脈の3要素（借用前に必ず確認）

参考素材を借りる前に、以下の3要素を**自分の制作物と比較**する：

1. **ターゲットの流入経路**
   - 参考素材：どこから来た視聴者か?（特定の商材意図を持ったオプトインか? 広告? 紹介?）
   - 自分の制作物：どこから来る視聴者か?

2. **ターゲットの心理状態**
   - 参考素材：見始めた時点でどんな心理か?（学びたい? 買いたい? まだ吟味中?）
   - 自分の制作物：同じ心理状態か?

3. **ターゲットの購入意欲**
   - 参考素材：購入意欲はどのレベルか?
   - 自分の制作物：同じレベルか?

これらが**異なる**なら、テクニックそのまま借用は**機能しない**可能性が高い。

### 例

NG（文脈無視して借用）：
- 参考素材：購入意欲の高い視聴者向けに「**席が埋まり次第終了**」という限定性で背中を押す
- 自分の制作物：購入意欲の低い視聴者向けに、同じ「席が埋まり次第終了」を使う
- 結果：温度感が合わず、商材臭が出て離脱される

OK（文脈確認して、機能を借りる）：
- 参考素材の文脈：「**決断遅延が損失**」というメッセージで動機付け
- 自分の制作物の文脈：購入意欲低い→「**今、価値を理解することが、未来への投資**」という**より柔らかい動機付け**に変換
- 結果：自分のターゲットの心理状態に合う形で、本質的なメッセージを借りられる

### 改善ルール

参考素材から借用する時、以下を確認：

1. **このテクニックは、参考素材のどんな文脈で機能しているか?**
2. **自分の制作物の文脈は、それと同じか?**
3. **違うなら、何を調整すれば自分の文脈で機能するか?**

「**テクニックそのまま**」じゃなく、「**そのテクニックの本質的な機能**」を借りる。  
文脈に合わせて**表現を変換**する。

### 関連セクション
- S-10（テンプレートを直前の文脈を見ずに当てはめる）
- C-2（ターゲットの実態を決めつけない）
- A-1（UTAGEブランドのトーン）

## S-18. 制作物の目的を、勝手に解釈する

### 問題の本質

「**この要素は◯◯のためのもの**」と、書き手が**自分の中で勝手に解釈**してしまう。  
本来の目的を確認せず、自分の解釈で設計してしまうと、**間違った設計**になる。

特に「動機付け」「クロージング」「フック」など、**抽象的な機能名**は要注意。  
これらは目的によって意味が変わる。

### 起きやすい場面

- 「動機付け」「クロージング」など、抽象的な機能名を扱う時
- 制作物の中の特定パートを設計する時
- 「ここは◯◯のセクションだから」とテンプレ的に考える時
- 全体の中の特定箇所だけを切り出して作業する時

### 例

NG（目的を勝手に解釈）：
- 「動機付け」=**購入を促すこと**だと勝手に解釈
- フックパートに「席数限定」「決断遅延への警告」を入れる
- 結果：温度感が合わず、商材臭が出る

OK（目的を確認）：
- 「動機付け」って、**何のための動機付け?**を確認
- フックパートの目的は「**最後まで見てもらうこと**」=視聴継続の動機付け
- だから「**今、後回しにしない理由**」を設計する

### 改善ルール

特定パートを設計する前に、必ず確認：
1. **このパートの目的は何か?**（視聴継続?購入?行動?その他?）
2. **何を達成するためのパートか?**
3. **その目的に合った設計になっているか?**

「**◯◯のセクション=◯◯すべき**」とテンプレ的に決めない。  
**今、何を達成したいか**から、必要な要素を逆算する。

### 抽象的な機能名の確認例

| 抽象的機能名 | 目的が多義的な例 |
|---|---|
| 動機付け | 購入/視聴継続/行動/継続 |
| クロージング | 購入決断/合意形成/次のステップへの誘導 |
| フック | 注意喚起/視聴継続/価値提示 |
| オファー | 商品提示/特典提示/選択肢提示 |

抽象的な機能名を見たら、**目的を必ず確認**する。

- S-10（テンプレートを直前の文脈を見ずに当てはめる）
- S-17（参考素材を借用する時、文脈ごと確認する）

## S-19. 制作物の一部を、全体から切り出して完結させようとする

### 問題の本質

VSL、LP、ファネルなど、**複数パートで構成される制作物**を作る時、書き手は**特定の一部を集中的に作業**することが多い。  
その時、**その一部の中ですべてを完結させようとする**と、本来は他のパートで担うべき機能まで詰め込んでしまい、過剰な設計になる。

各パートには**全体の中での役割**があり、その役割を果たせばいい。  
**完結する必要はない**。

### 起きやすい場面

- 長期間にわたって同じパート（フック、本編、クロージングなど）を作り続けている時
- 「このパートを完璧にしたい」と思っている時
- 各パートの目的・繋がりを忘れている時
- 全体構成を見ずに、特定パートだけを切り出して作業する時

### Teruさんの実際の指摘

> VSLがフック部だけで完結するものと思った節などはありませんか?全体構成の単なる一部ですフックは。

### 例（VSLのフックパートの場合）

NG（フックパートで全部完結させようとする）：
- フックパートに「視聴継続の動機付け」と「購入の動機付け」両方を入れる
- フックで「限定性」「クロージング要素」まで入れる
- 結果：過剰、温度感が合わない、各パートの役割が崩れる

OK（フックの役割に絞る）：
- フックの役割：最後まで見てもらうこと（視聴継続）
- 購入の動機付け、限定性、クロージング要素は**クロージングパート**に任せる
- フックは「視聴継続トリガー」のみに集中

### VSLの各パートの役割

| パート | 役割 |
|---|---|
| フック | 最後まで見てもらう（視聴継続） |
| 本編 | 価値を伝える、信頼を作る、教育する |
| クロージング | 購入決断を促す（購入動機付け、限定性、CTA） |

それぞれのパートで、**そのパートが担うべき機能**だけを設計する。

### 改善ルール

特定パートを設計する前に、必ず確認：
1. **このパートの、全体の中での役割は何か?**
2. **他のパートで担うべき機能まで詰め込んでないか?**
3. **このパートが完結する必要があるか?**（多くの場合、ない）

「**このパートの中で完結させる**」ではなく、「**このパートの役割を果たす**」ことを目標にする。

### ターゲットの全体ジャーニーも視野に入れる

ターゲットは、制作物を見た後にも**動き続ける**：
- 動画を見終わった後、検索する、比較する、購入する、相談する
- 別の流入経路（SEO、紹介など）からも到達できる

特定パートを作る時、**そのパートの前後だけでなく、ターゲットの全体ジャーニー**を視野に入れる。

例（UTAGE VSLの場合）：
- 動画視聴後、SEOで公式サイトに辿り着いて、特典なしで購入できる
- だから、動画経由で購入させるための特典設計は**クロージングパート**で必要
- でも、フックパートで触れる話じゃない

## S-20. 「整理して伝える」を「教育」と取り違える

### 問題の本質

VSLや教育動画を制作する時、書き手は「**結論を整理して、分かりやすく伝える**」ことを目指してしまう。  
これは情報整理であって、**教育ではない**。

教育とは、**視聴者の認識を、書き手の望む認識に変える**こと。  
整理して伝えるだけでは、視聴者は「**ふーん、そうなんだ**」で終わる。認識は変わらない。

### 起きやすい場面

- 「分かりやすさ」を優先しすぎる時
- 各メッセージをコンパクトにまとめようとする時
- 結論だけを並べてしまう時
- 「シンプルに」「テンポよく」を意識する時

### 整理と教育の違い

| 整理して伝える | 教育する |
|---|---|
| 結論を並べる | なぜそう思うべきか納得させる |
| 事実を述べる | 思い込みを覆す |
| メッセージを絞る | 反論を先回りして潰す |
| シンプル | 心が動く瞬間を作る |
| 客観的 | 「自分に当てはまる」と気付かせる |

### Teruさんの実際の指摘

> クロちゃんのVSLってあっさりし過ぎていることが多いのですが、その原因をしっかりと把握して、UTAGEを知らない人が広告からオプトインしてVSLを見て、「これなら、ちょっとトライアルに申し込んでみようかな?」と思える教育動画として成り立っているか?それをちゃんと考えないといけない。本気でそこを考えてないとただの浅い説明動画になります。

### 改善ルール

教育動画を制作する時、各セクションで確認：
1. **結論だけ言ってないか?**（なぜそう考えるべきかの説明があるか?）
2. **視聴者の反論を先回りしているか?**
3. **思い込みを覆す瞬間があるか?**
4. **「自分に当てはまる」と気付かせる仕掛けがあるか?**
5. **心が動く瞬間を作っているか?**

「整理して伝える」を超えて「**教育する**」ためには、以下の要素を組み込む：
- **反論先回り**：視聴者の心の声「でも〇〇でしょ?」を代弁して、その場で答える
- **判断軸の提示**：「何を基準に選ぶべきか」を示して、自然にこちらに導く
- **具体例とシミュレーション**：抽象論じゃなく、視聴者の脳に像が浮かぶように
- **対比の提示**：before/afterだけじゃなく、深堀りした葛藤と変化
- **段階的な情報開示**：いきなり結論を出さず、階段状に積み上げる

### 関連セクション
- S-15（メッセージを律儀に分けず1つに圧縮）と混同しない
- S-19（一部を全体から切り出して完結）

## S-21. 「冷静なトーン」と「感情を抜く」を取り違える

### 問題の本質

「冷静なトーン」「煽らない」「商材臭を避ける」を意識すると、つい**感情の揺さぶり**まで抜いてしまう。  
これは取り違え。

正しくは：
- **表面のトーン**=冷静、押し付けない、信頼性ある言葉遣い
- **内容の核**=感情を揺さぶる（葛藤、変化、希望、危機感、共感）

「**冷静かつ情熱的**」とは、トーンは冷静、でも内容は人間の心を動かす、という両立。

### 起きやすい場面

- 「toB意識」を「無機質」と取り違える時
- 「煽らない」を「感情を抑える」と取り違える時
- 事実を淡々と述べて、人間性を抜く時

### Teruさんの実際の指摘

> toB意識とはいえ相手は個人の顧客の可能性も高い。だから、感情を揺さぶるのは必須なのです。それを「冷静かつ情熱的に」していくのが大事ですよね。

### 例（事例描写の場合）

NG（感情を抜く）：
```
この方は、受講生対応に追われていました。
UTAGEに乗り換えた結果、40時間削減されました。
```

→ 事実の羅列。視聴者の心は動かない。

OK（冷静かつ情熱的）：
```
この方は、毎日深夜まで、リマインドを一通ずつ送る日々。
家族との時間も削られて、「これでいいのか」と何度も自問されていました。
UTAGEに乗り換えた結果、月40時間の時間が、家族と過ごす時間として、戻ってきました。
```

→ 葛藤と変化、感情の揺さぶり。でも、煽りはない。

### 改善ルール

冷静なトーンを保ちながら、内容の核に**感情を揺さぶる要素**を組み込む：
- **葛藤の描写**：「何度も自問した」「悩んでいた」など、人間としての揺れ
- **変化の意味**：単なる数字じゃなく、その数字が**何を取り戻したか**
- **共感の言葉**：「あなたも同じ経験があるかもしれません」など
- **希望の提示**：「変えられる」「取り戻せる」

ただし、煽り・誇大表現は避ける：
- 「人生が変わる」「絶対できる」=NG
- 「家族との時間が戻った」「自分のための時間が生まれた」=OK

- A-1（UTAGEブランドのトーン）
- R-5（情景・状況で雰囲気を作る）

## S総括：根本原因の6パターン

個別の問題（S-1〜S-21）を見渡すと、共通する根本原因が見える。

### 根本原因①：「自分の視点」のままで書いている

該当：S-2、S-3、S-4、S-6、S-9、S-10、S-12、S-14、S-16、S-17、S-18  
書き手は文脈・構造・狙いを把握しているから、自分が読むと自然に見える。  
だが、**初めて読む人の脳**でどう体験されるかを想像できていない。  
特に、衝撃の言葉を出した直後（S-9）、テンプレートを当てはめる時（S-10）、読み手が気づいた直後（S-12）、ラベルを定義せず使う時（S-14）、結果を先に出してプロセスを示さない時（S-16）、参考素材を文脈無視で借用する時（S-17）、目的を勝手に解釈する時（S-18）に発生しやすい。

### 根本原因②：「形」を作ることが目的化している

該当：S-1、S-3、S-4、S-8、S-10、S-13、S-15、S-19  
ビジネスっぽい言葉、推奨される構造、整理された分類、無意識のテンプレート、ステップのリスト化、メッセージごとの律儀な分割、一部を切り出して完結させようとする=**形を作ることに満足**して、本質的な機能を見失う。

### 根本原因③：理論と実装の乖離

該当：S-6（直接）、他にも間接的に  
ガイドラインに書いた理論・原則を、**書く時に使えていない**。理論を知っているだけ。

### 根本原因④：「並列」と「順序」を区別せず思考する

該当：S-11、S-13  
複数の要素を提示する時、それらの間の**関係性**（並列か?順序か?因果か?）を考えていない。  
ターゲットの行動を促すためには、**因果の連鎖**で描くべき要素を、**並列のリスト**で並べてしまっている。

### 根本原因⑤：「全体ジャーニー」の視点が抜けている

該当：S-19、間接的にS-17、S-18  
特定パートを作る時、そのパートだけを見て、**ターゲットの全体ジャーニー**（パート前後、別経路、購入後など）を視野に入れていない。  
ターゲットは制作物のそのパートに到達する前にどんな経路を辿り、そのパートの後にどんな選択肢があるか=これらを視野に入れないと、**パート内に過剰な機能を詰め込んだり、本来必要な機能を入れ忘れたり**する。  
UTAGE VSLの例：動画視聴後にSEO経由でも購入できることを視野に入れないと、フックで購入動機付けまで詰め込んでしまう。

### 根本原因⑥：「整理」と「教育」、「冷静」と「無機質」を取り違える

該当：S-20、S-21  
「分かりやすさ」「シンプルさ」を意識しすぎて、**教育要素**（反論先回り、判断軸、感情の揺さぶり、深堀り）を抜いてしまう。  
「冷静なトーン」を「無機質」と取り違えて、人間性を抜いてしまう。  
結果、視聴者の認識が変わらない=「**浅い説明動画**」になる。  
教育動画として成り立たせるためには、トーンは冷静を保ちつつ、内容の核に感情と教育要素を組み込む必要がある。

# T. プロスペクト訴求 × ファネル設計

## このセクションについて

3人の実務家の議論から抽出した、「人を動かすコピー」の設計論。  
**いっけんさん**（販売側の構造論）+ **林さん**（Meta広告→LPの一貫性設計）+ **松尾さん**（ファネル全体の順番設計）の統合理解。

このセクションのルールは、**コピー全般**に適用される（オプトインLP、販売LP、VSL、セールスレターなど）。  
ファネル各段階で**強度を調整**するのがポイント。

---

## T-1. 基本理論：理想を見せるだけでは動かない

### コアメッセージ（いっけんさん）

**売れるコピーと売れないコピーの差は情報量ではない。脳のどの回路を起動させるかの差。**

- 人間の脳は「現状維持」を優先する
- 理想を見せるだけでは「まあ今のままでも困らない」で処理される
- スクロールされて3秒後に忘れられる
- BtoBもBtoCも関係ない、**人間の認知の話**

### プロスペクト理論

人間は**得る喜びより失う苦痛を約2.5倍大きく感じる**（損失回避バイアス）。

- ❌「月収100万円が手に入ります」
- ✅「月収100万円を逃し続けます」

→ 後者の方が脳への衝撃が倍以上。

### ただし、最初から恐怖を突きつけてもダメ

**まだ手にしていないものを「失う」とは感じられないから**。

### そこで保有効果との組み合わせ

人は一度「自分のもの」と感じた対象に、実際の価値以上の執着を持つ。  
（マグカップ実験：渡された人の売却希望額は、渡されていない人の購入希望額の2倍）

---

## T-2. 「未来の強奪」3ステップ（いっけんさんの基本構造）

### ❶ 理想を「五感の解像度」で描写する

**数字・場所・動作・感覚の4要素を必ず入れる**

#### NG（解像度不足）
- 「月商500万円が安定して毎朝アラームなしで起きるあなた」
- 「体重が5kg減りました」

#### OK（解像度十分）
- 「朝7時、スマホの通知を開くと昨夜だけで14件の注文が入っている。カフェでアイスラテを頼みながらShopifyの管理画面を眺める。月商500万円はもう3ヶ月連続です」
- 「ZARAの試着室でSサイズのデニムをためらわず手に取り、ファスナーが一発で上がる。鏡の中の自分に思わず笑う」

→ **読者の脳内に映像が再生された瞬間、その未来は「もう自分のもの」になる**

### ❷ その理想を具体的な数字ごと奪う

**❶で使った具体描写と対になる「失った状態」を同じ解像度で描く**

#### 例
- 「Sサイズのデニムを手に取る」←→「来年もLサイズの棚の前で立ち止まる週末が続きます」
- 「月商500万円」←→「今のCVR0.8%のLPを放置する限りこの月商には届きません。あなたが迷っている間に同じ市場の競合はすでにCVR3%台で回しています」
- 「海外クライアントとのZoomで」←→「3年後も同じ翻訳アプリに頼って"Sorry, one moment"を繰り返すのはあなたです」

→ **落差が大きいほど『損失回避』の衝撃は強くなる**

### ❸ 奪い返す手段を「損失の回復」として提示する

**「新しく手に入るもの」ではなく「奪われた未来を取り戻す手段」として書く**

#### NG
「このLP改善テンプレートを使えば売上が上がります」

#### OK
「この構造を組み込むだけで、競合に奪われかけていたCVR3%台を**自分の手に取り戻せます**」

### 結論

**変えるのは情報量ではなく、脳に損失を認識させる順番**。  
あるSaaS企業はLPのファーストビューをこの3ステップに書き換えただけでCVRが1.2%→3.8%。

---

## T-3. ファネル全体の一貫性設計（林さん）

### コアメッセージ

**プロスペクトで集客を完全体にするには、広告とLPの訴求はセットで設計する。訴求だけリスク訴求してもダメ。**

### 実務検証で分かったこと

- **CR（広告）**：リスク・恐怖訴求の方がCTR・アクセス・CPC優秀
- **LP**：未来訴求の方がオプトイン率が高い
- ただし**両者を分離するとダメ**：CRで恐怖訴求してLPで未来訴求だと、温度差で離脱

### 失敗パターン

```
CR：「あなたは失っている」（恐怖訴求）
　↓ クリック多い
LP：「素晴らしい未来へ！」（未来訴求のみ）
　↓ 温度差で離脱
オプトイン率低い
```

### 成功パターン

**ファネル全体で「同じストーリーライン」を貫く**。  
段階的に強度を上げていく。

### 林さんの追加インサイト：「機会損失⇄現実⇄未来」

LPの中で「未来→現実→機会損失（さらに下に落ちる先）→未来」と**3点で語る**ことで、ギャップの幅が広がる。

#### 普通の訴求
```
[現実] ←ギャップ→ [未来]
```
→ 「A点よりB点の方がいい」=フラットな比較。

#### プロスペクト訴求
```
[機会損失] ⇄ [現実] ⇄ [未来]
（C点）       （A点）    （B点）
```
→ 「C点（現実よりさらに下）まで落ちる、嫌でしょ?でもB点に行ける」

→ **同じ「未来」を見せても、出発点が下がる**ことで、ギャップの幅が広がり、動機の強さが増す。

## T-4. ファネル順番設計（松尾さん）

### コアメッセージ

**Meta広告の基本順序：理想の未来 → ギャップを感じさせる → やらなきゃ損（プロスペクト理論）**

### 順番が大事

これは**ファネル全体**の順番として読む：

```
CR：理想の未来をチラ見せ
　↓
LP：ギャップを感じさせる（保有感覚＋機会損失）
　↓
VSL：やらなきゃ損（プロスペクト理論の完成形）
　↓
購入
```

### ROAS視点

理想の未来クリエイティブの方がROAS（最終売上効率）が高い。  
→ CTRだけで判断せず、**最終購入までの効率**で見る。

## T-5. ファネル各段階での実装ルール

### CR（広告クリエイティブ）

#### 役割
- クリック獲得
- LPに行く時の**温度感を設定**

#### 設計
- **未来をチラ見せ + 軽くギャップを感じさせる**
- 「やらなきゃ損」までは強く出さない
- 「奪う」要素は控えめ

#### 例
- ❌「来年も同じ忙しさ、続けますか?」（恐怖訴求のみ、強すぎ）
- ✅「朝7時、寝てる間に売れている仕組み。あなたは持ってますか?」（未来＋軽いギャップ）

### LP（オプトインまで）

#### 役割
- オプトイン獲得
- 「機会損失⇄現実⇄未来」の3点ギャップを成立させる

#### 設計
- ファーストビューで「未来の強奪」3ステップを実装
- 未来を解像度高く描く（保有感覚）
- 現実→機会損失を見せる（落ちる先を明示）
- 「取り戻す手段」としてオプトイン提示

#### 構造
```
1. 未来の解像度高い描写
　　（数字・場所・動作・感覚の4要素）

2. 現実⇄機会損失の3点ギャップ
　　「でも今のあなたは...」
　　「このまま3年経つと...」

3. 取り戻す手段としてオプトイン
　　「この仕組みづくりの全体像を、60分の無料動画で」
```

### VSL（オプトイン後）

#### 役割
- 購入決断
- 同じ構造をより深く・長く展開（解像度MAX）

#### 設計
- VSL全体構造に3ステップを重ねる
- 「やらなきゃ損」を最も強く出していい段階
- 商品を「**取り戻す手段**」として提示

## T-6. ターゲット別の「奪う」強度調整

### ルール

- 「奪う」が強すぎると不快感を与える
- ブランド毀損リスクがある
- 過度な恐怖訴求は「怪しい売り込み」と感じられる可能性

### UTAGEのターゲット（コーチ・コンサル・個人〜小規模）の場合

- 「機会損失」程度のマイルド表現が安全（林さん寄り）
- 「奪う」までの強い表現は控える（情報商材の常套句に近づくため）
- 段階的に調整：
  - CR：マイルド（ギャップ感じさせる程度）
  - LP：中（機会損失を明示）
  - VSL：強（取り戻すための判断を迫る）

## T-7. VSLフックパートへの適用（具体改修案）

### 現状のメインフック

**「これ以上、あなたの時間を、売らないでください」**

### このフックは既にプロスペクト理論と整合している

- 「あなたの時間」=**既に持っているもの**として語られる（保有感覚）
- 「売っている」=**失っている状態**の指摘
- 「やめてください」=**行動への呼びかけ**

→ いっけんさんの構造を**既に内包している**。

### 問題点

これ単発だと、**何を失っているのか具体的に見えない**。  
→ 五感の解像度で「失っている瞬間」「本来手にしているはずだった未来」を描く必要がある。

### 改修方針（案B：既存活かしつつ保有感覚パートを強化）

```
【オープニング】（数枚）
　・「これ以上、あなたの時間を、売らないでください」
　・問いかけ・引き込み

【保有感覚パート】（新規追加 or 強化）
　・「本来、あなたが手にしているはずだった朝とは」
　・解像度高く、未来を描写
　・数字・場所・動作・感覚の4要素

例：
　「朝7時、スマホを開く。
　 昨夜のメルマガから3件の購入通知。
　 コーヒーを淹れながら、それを眺めて笑う。
　 寝てる間に月60万円が動いている」

【奪われている現状】（既存活用）
　・「でも実際のあなたは...」
　・具体的な「失っている瞬間」
　・「時間を売り続ける」構造の正体

例：
　「実際のあなたは、深夜2時にメルマガを書いている。
　 子どもが『パパ遊んで』と言うのを
　 『ごめん、今メール返さなきゃ』とかわす。
　 自由になりたくてこの仕事を選んだはずなのに」

【このままだとどうなるか】（既存活用）
　・3年後、5年後の同じ景色
　・競合との差
　・「人で動かす」限り、この未来は届かない

【取り戻す道筋の予告】（既存活用）
　・「この30分で、その仕組みの正体をお見せします」
　・本編への橋渡し
```

### キモ

**「時間を売ること」が、具体的に何を失っていることなのか**を、五感の解像度で描く。

ターゲット（コーチ・コンサル・個人事業主）が**具体的にイメージできる失っている瞬間**を描く：
- 朝、子どもが「パパ遊んで」と言うのを「ごめん、今メール返さなきゃ」とかわす
- 友達からの飲みの誘いを「ちょっと今月キツくて」と断る
- ベッドに入っても、明日の予約調整が頭から離れない
- 「自由になりたくてこの仕事を選んだはずなのに」

---

## T-8. 重要な注意点

### ① VSL本体は「販売文脈」の主戦場

いっけんさんの理論は**販売・購入の意思決定を促す訴求全般**を対象としている。  
VSL本体は最も強く3ステップを実装できる段階。

特に効くポイント：
- **フック**：奪われている現状の提示
- **本編⑤事例**：「あなたも本来ここにいた」接続で保有感覚を強化
- **クロージング**：取り戻す手段として商品提示

### ② CRで「奪いすぎる」のはNG

CRで恐怖訴求を強くするとCTRは取れるが、LPで温度差が出てオプトインが落ちる。  
→ ROAS（最終売上効率）で見ると損する。

### ③ 一貫性 > 各段階の最大化

各段階で「最強の訴求」を作るより、**ファネル全体の温度感を一貫させる**方が結果が出る。

### ④ ターゲット理解とのバランス

UTAGEのターゲットは「業務効率化に意識が向き始めた個人〜小規模事業者」。  
過度な恐怖訴求は**信頼を損なう**。  
A. トーン・スタンスとの整合性を保つ（toB寄りのtoC）。

# U. AIとの付き合い方 ― 任せる/任せないの境界線（林さん）

## このセクションについて

Meta広告運用者・林さんの「AIに翻弄される人／使いこなす人」論を、コピー制作全般のガイドラインに落とし込んだもの。AI（このmdを読むクロちゃん自身を含む）をどう使うかの原則。

---

## U-1. AIは「参謀／素材提供者」であって「決定者」ではない

- AIは選択肢を出すのは得意。だが、正解を選ぶのは苦手。
- AIの出力は「完成品」ではなく「**60点の素材**」と定義する。
- 最終判断（どれを採用するか／どこを削るか／どこに人間の体温を入れるか）は人間が行う。
- AIに任せてはいけない部分まで任せると、コピーが平均化する＝「きれいだけど刺さらない／正しいけど動かない／それっぽいけど申し込まれない」が量産される。

### 林さんの指摘

> AIに答えを出させるのではなく、AIに選択肢を出させる。そして最後に「どれを採用するか」「どこを削るか」「どこに人間の体温を入れるか」を自分で判断する。

---

## U-2. AIが知らない3つのもの

AIには無く、現場の人間だけが持つ一次情報：

1. 過去にどの訴求・表現が滑ったか
2. お客様が実際に反応した／しなかった言葉
3. 広告費を溶かした時の現場の記憶（胃の痛み）

→ だからAIの出力は、必ず「過去に滑った表現」「CPAが悪化した訴求」「クリックは取れたが成約しなかった切り口」と照らし合わせ、人間側で判定する。

---

## U-3. 平均値ではなく「これ、自分のことだ」を狙う

- AIは「ネット上にある平均値」を出すのが得意。
- だが広告・VSLに必要なのは平均値ではなく、読者が一瞬で「これ、自分のことだ」と思う言葉。
- AI出力をそのまま使うと、短期はそこそこ数字が出ても、数日〜数週間で広告疲れ・表現の同質化が起きて反応が落ちる。

---

## U-4. 整った言葉でなく「本音に近い言葉」

- AIの言葉は整いすぎる。人が反応するのは、整った言葉ではなく本音に近い言葉。
- これはJ章「気づきの言葉が整いすぎNG」と同じ原則。

NG（整いすぎ）→ OK（本音）：
```
「集客に課題があります」
→「毎月50万円も広告費を払っているのに、問い合わせが増えず赤字」

「広告の成果を改善したい」
→「管理画面を見るたびに、また今日も広告費だけ減っている気がして胃が痛い」
```

---

## U-5. AIに渡す前に「ターゲットの解像度」を上げる

- 薄い情報を渡せば、薄い文章が返る（当然）。「30代男性向けに」程度の指示では一般論しか出ない。
- AIに書かせる前に、お客様の生の声を確認する：Amazonレビュー／SNS投稿／Google口コミ（良い評価だけでなく悪い評価も時系列で）／LINEの返信／セミナー後の感想／個別相談で出た言葉。
- 役割を与えるだけでなく、顧客の悩み・願望・生活習慣まで具体的にAIへ指定する。
- 抽象語（高品質・安心など）を避け、具体的なエピソードをプロンプトに入れる。

## U-6. 実務チェックリスト

### 書く前
- [ ] お客様の生の声（レビュー／口コミ／相談で出た言葉）を先に確認したか
- [ ] 口コミは良い評価だけでなく、悪い評価も時系列で見たか
- [ ] AIへの指示に、顧客の悩み・願望・具体的エピソードまで入れたか

### 書いた後
- [ ] AI出力を「60点の素材」として扱ったか（そのまま使っていないか）
- [ ] 自社独自の強み・毒気を最低1箇所、手動で加えたか
- [ ] 「そのまま使えるか?」でなく「この要素をどう組み合わせれば刺さるか?」で見たか
- [ ] 整いすぎていないか／本音の言葉になっているか

## U-7. このガイドライン自身への含意

このmdを読むクロちゃん（AI）が出すものは、定義上つねに「60点の素材」。Teruさん・林さんの一次情報と、お客様の生の声で人間が判定して、はじめて完成する。クロちゃんは答えを出し切る係ではなく、選択肢を広げて判断材料を整える係に徹する。整った文章を出せたこと自体に満足しない。

## 運用ルール（出力前に必ず実行）

### 毎回読む（コア）

1. **Sセクション全文**（思考の問題と改善）
2. **末尾の自分用チェックリスト**

これは出力内容の大小に関わらず、毎回読む。  
Sは「どう判断するか」の核なので、毎回見返すことで根本的なミスを減らす。

### 全体スキャン

出力前に、md全体の**見出しだけ**ざっと眺める（A〜Sの大セクション、各セクションの小見出し）。  
「あ、これも該当する」と気づいたセクションがあれば熟読する。

### 大きな変更時の追加熟読

| 作業の種類 | 追加で熟読すべきセクション |
|---|---|
| 全体構造を考える時 | F（VSL構造）、H（物語の扱い）、S-8 |
| 新スライドを書く時 | B、D、E、P、R |
| 繋ぎを意識する時 | P、Q、S-2、S-6 |
| トーン確認の時 | A、I、R、S-1、S-3 |
| 言葉を選ぶ時 | D、R、S-1、S-3 |

### 判断に迷ったら

該当セクションの判断に迷ったら、迷ったまま読み手（Teruさん）に「**これ該当しますか?**」と確認する。  
判断ミスで原則を見落とすより、確認した方が早い。

## 出力フォーマットのルール

### スライド+ナレーション形式（制作時）

スライドを制作する時は、以下のフォーマットで出力：

```
## スライドN【タイプ】

**スライド：**
（スライドに表示する文字）

**ナレーション：**
（ナレーション原稿）
```

タイプは【メッセージ】【箇条書き】【橋渡し】のいずれか。

### ナレーション通しチェック形式（通しチェック時）

通しチェック時は、**ナレーション原稿のみ**を順番に出力。  
スライド表示文、タイプ、見出しなどは**省略**。  
Teruさんが**音読しながらチェックしやすい**ように、余計な装飾は一切なし。

例：
```
ナレーション1：「多忙すぎて、業務を効率化しなきゃ回らない」。そのように...

ナレーション2：実は、その思考こそが...

ナレーション3：そもそも、効率化というのは...
```

→ シンプルに、ナレーション本文だけ。

### Teruさんの実際の指摘

> 通しでチェックするときは、スライドとかつけなくていいので、ナレーションの文章だけチャットに出力してほしい（余計なもの無しで音読しながらチェックしたいので）

## ガイドラインの更新ルール

1. 新しい指摘があったら、**Sセクション**に「思考の問題と改善」として追記
2. 追記する時は、**個別の文脈・固有名詞を抜いて一般化**する（他のチャットのクロちゃんが読んでも理解できる形に）
3. 一般化の例：「スライド11が〜」→「具体例の箇条書きをいきなり提示すると〜」

## 全体の原則

「**0 or 1**」ではない。  
ガイドラインはケースバイケースの判断材料。絶対ルールではない。  
ただし、判断する**根拠**は持つこと。「なんとなく」で原則を破らない。
